LangGraph constructs and deploys stateful, long-running AI agents by orchestrating their interactions using computational graphs. The framework provides tools for defining, executing, and managing complex agent workflows.

The framework enables users to define computational graphs where nodes represent individual processing steps, such as calling a large language model or using an external tool. Edges define the flow of execution between these nodes, allowing for dynamic decision-making and iterative processes. A Pregel-inspired execution model orchestrates graph execution, managing tasks and state updates during iterative computations. For execution orchestration, see [Pregel Execution Model and Graph Orchestration](https://codewiki.google/github.com/langchain-ai/langgraph#langgraph-core-framework-pregel-execution-model-and-graph-orchestration). [Graph Definition and Compilation](https://codewiki.google/github.com/langchain-ai/langgraph#langgraph-core-framework-graph-definition-and-compilation) further describes graph construction.

The system manages mutable state within these graphs through a modular channel system. Channels allow agents to maintain context and memory across interactions, supporting long-running conversations and complex stateful applications. They offer various mechanisms for handling data, including single values, transient values, and aggregated values. [Channels and State Management](https://codewiki.google/github.com/langchain-ai/langgraph#langgraph-core-framework-channels-and-state-management) provides further details.

LangGraph provides persistence and checkpointing mechanisms to ensure agent state endures. This enables human-in-the-loop interactions and memory across conversational turns by saving and restoring the graph's state. Various storage backends, including in-memory, SQLite, and PostgreSQL, support these capabilities, along with serialization, caching, and key-value stores. [Persistence and Checkpointing](https://codewiki.google/github.com/langchain-ai/langgraph#persistence-and-checkpointing) describes these features.

For accelerated development, LangGraph offers prebuilt components that simplify common agent patterns. These include high-level APIs for creating conversational agents and robust mechanisms for executing external tools. For details on these components, see [Prebuilt Agent Components](https://codewiki.google/github.com/langchain-ai/langgraph#prebuilt-agent-components). A command-line interface (CLI) streamlines project creation, local development, and Docker-based deployment. The Python SDK offers programmatic control over API resources, including assistants, threads, and runs, complete with authentication and streaming capabilities. [Command-Line Interface (CLI) and Development Tools](https://codewiki.google/github.com/langchain-ai/langgraph#command-line-interface-cli-and-development-tools) and [Python SDK for LangGraph](https://codewiki.google/github.com/langchain-ai/langgraph#python-sdk-for-langgraph) elaborate on these development tools.

## LangGraph Core Framework

link

zoom\_in

LangGraph is a foundational framework for building and deploying stateful, long-running AI agents using a graph-based approach. It provides core components for defining, building, and executing computational graphs, managing dependencies, and structuring agent interactions. The framework draws inspiration from graph processing models like Pregel and Apache Beam, as well as the graph interface of NetworkX, to enable customizable architectures, long-term memory, and complex task handling through explicit definitions of states and transitions.

The core of LangGraph's functionality resides in its graph-based orchestration. Developers can define computational graphs where nodes represent computational steps (e.g., calling an LLM, using a tool) and edges represent transitions between these steps. This structure facilitates the creation of complex workflows for AI agents, allowing for iterative processes and dynamic decision-making. The definitions of these graphs are compiled into executable instances, providing a structured approach to agent design.

A key aspect of LangGraph is its ability to manage mutable state within these computational graphs. This state management system is robust and supports various mechanisms for handling values, including single values, values with delayed availability, and aggregated values. This allows agents to maintain context and memory across multiple interactions, which is crucial for long-running conversational AI and other stateful applications. The framework also provides mechanisms for injecting runtime context, such as whether a step is the last one or the remaining steps in a sequence.

The framework supports dynamic control flow within these graphs. This includes conditional routing, where the path of execution can change based on the current state or output of a node. It also offers command objects that enable complex graph control, such as updating state, resuming interrupted workflows, or navigating to specific nodes. These capabilities are foundational for developing human-in-the-loop workflows, where human intervention can pause execution, review state, and guide the agent's next steps.

For more detailed information on specific components of the framework, refer to the following sections: [Pregel Execution Model and Graph Orchestration](https://codewiki.google/github.com/langchain-ai/langgraph#langgraph-core-framework-pregel-execution-model-and-graph-orchestration) for execution orchestration, [Graph Definition and Compilation](https://codewiki.google/github.com/langchain-ai/langgraph#langgraph-core-framework-graph-definition-and-compilation) for graph construction, [Channels and State Management](https://codewiki.google/github.com/langchain-ai/langgraph#langgraph-core-framework-channels-and-state-management) for state handling, [Functional API and Runtime Configuration](https://codewiki.google/github.com/langchain-ai/langgraph#langgraph-core-framework-functional-api-and-runtime-configuration) for defining executable units and runtime context, and [Dynamic Control Flow and Commands](https://codewiki.google/github.com/langchain-ai/langgraph#langgraph-core-framework-dynamic-control-flow-and-commands) for conditional routing and graph control.

### Pregel Execution Model and Graph Orchestration

link

zoom\_in

LangGraph's core is a Pregel-inspired execution model, which provides a computational backbone for building and deploying stateful, long-running AI agents. This model orchestrates graph execution, manages channels, handles checkpointing, and facilitates synchronous and asynchronous task scheduling for iterative computations.

The [`Pregel`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/main.py#L321) class, defined in [`libs/langgraph/langgraph/pregel/main.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/main.py), serves as the central orchestrator for defining and executing stateful agent graphs. It manages the flow of data and control between different nodes, which encapsulate specific agent logic. Nodes are constructed using [`NodeBuilder`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/main.py#L159), allowing developers to specify input subscriptions, processing logic, and output writes.

The execution of the graph proceeds through an iterative loop, implemented by the [`PregelLoop`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_loop.py#L140), [`SyncPregelLoop`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_loop.py#L957), and [`AsyncPregelLoop`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_loop.py#L1133) classes in [`libs/langgraph/langgraph/pregel/_loop.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_loop.py). This loop handles the loading and saving of graph state via checkpoints, updates channels, and schedules tasks. Each iteration, or "superstep," involves preparing tasks using logic in [`libs/langgraph/langgraph/pregel/_algo.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_algo.py), executing them, applying any resulting writes to the graph's state, and synchronizing for the next step. The [`PregelRunner`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_runner.py#L122) in [`libs/langgraph/langgraph/pregel/_runner.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_runner.py) further manages the concurrent execution of these tasks.

State management is fundamental to this model, primarily handled through a robust channel system. Channels, detailed further in [Channels and State Management](https://codewiki.google/github.com/langchain-ai/langgraph#langgraph-core-framework-channels-and-state-management), represent mutable state within the graph, enabling communication and data flow between nodes. Operations like [`read_channel`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_io.py#L23) and [`map_input`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_io.py#L81) from [`libs/langgraph/langgraph/pregel/_io.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_io.py) manage how data is read from and written to these channels, including transforming external inputs into internal channel updates.

Checkpointing, elaborated in [Checkpoint Saving and Retrieval](https://codewiki.google/github.com/langchain-ai/langgraph#persistence-and-checkpointing-checkpoint-saving-and-retrieval), allows for the persistence and restoration of the graph's entire state. Functions within [`libs/langgraph/langgraph/pregel/_checkpoint.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_checkpoint.py) enable the creation, manipulation, and restoration of [`Checkpoint`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py#L172) objects, which are crucial for resuming interrupted workflows or analyzing execution history.

Task scheduling and execution support both synchronous and asynchronous operations. The framework includes retry mechanisms for [`PregelExecutableTask`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L234) instances, implemented in [`libs/langgraph/langgraph/pregel/_retry.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_retry.py), which provide resilience against transient failures with configurable backoff and jitter. User-defined functions can be converted into [`Runnable`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/tests/model.py#L15) instances for integration into the Pregel execution model using utilities in [`libs/langgraph/langgraph/pregel/_call.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_call.py), allowing for seamless incorporation of custom logic.

The system also incorporates mechanisms for dynamic control flow and interruption, allowing agents to pause for human input or navigate complex decision paths. This includes handling of [`Command`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L349) objects for advanced graph control, discussed in [Dynamic Control Flow and Commands](https://codewiki.google/github.com/langchain-ai/langgraph#langgraph-core-framework-dynamic-control-flow-and-commands). The overall graph structure can be visualized and debugged using tools that generate a [`Graph`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/README.md?plain=1#L73) representation, as seen in [`libs/langgraph/langgraph/pregel/_draw.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_draw.py), which simulates graph steps to discover edges and conditional transitions.

### Graph Definition and Compilation

link

zoom\_in

Computational graphs in LangGraph are defined and structured using the [`StateGraph`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/state.py#L111) class, which serves as a builder for state-based workflows. This class enables the construction of complex AI agents by allowing developers to specify individual processing units, known as nodes, and define the flow of execution between them.

Nodes, which are functions or [`Runnable`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/tests/model.py#L15) instances, are added to the graph using the [`add_node`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/state.py#L288) method. The connections between these nodes, or edges, are established via the [`add_edge`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_draw.py#L280) method, directing the flow from one node to another. For more dynamic control, [`add_conditional_edges`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/state.py#L621) introduces branching logic, where the next node to execute is determined by the output of a specified function. This allows for adaptive workflows based on intermediate results.

Special entry and finish points guide the overall execution. The [`set_entry_point`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/state.py#L713) method designates the initial node where the graph begins processing, while [`set_conditional_entry_point`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/state.py#L726) allows the starting point to be dynamically selected based on the input. Conversely, [`set_finish_point`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/state.py#L747) marks a node as a terminal state for the graph's execution.

Once the graph's structure is fully defined with nodes, edges, and entry/finish points, the [`StateGraph`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/state.py#L111) is compiled into an executable [`CompiledStateGraph`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/state.py#L912). This compilation process transforms the high-level graph definition into an instance that can be run, leveraging an underlying Pregel-inspired execution model. The [`CompiledStateGraph`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/state.py#L912) then provides methods like [`invoke()`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/agents/run_agents.md?plain=1#L12) and [`stream()`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/how-tos/streaming.md?plain=1#L408) to execute the defined workflow, managing state and inter-node communication efficiently. The architecture of this execution model is further detailed in [Pregel Execution Model and Graph Orchestration](https://codewiki.google/github.com/langchain-ai/langgraph#langgraph-core-framework-pregel-execution-model-and-graph-orchestration).

### Channels and State Management

link

| Channel Type | Stores | Multiple Updates in a Step | Persistence (Checkpointing) | Value Clearing/Aggregation |
| :-- | :-- | :-- | :-- | :-- |
| `AnyValue` | The last received value | Stores the last value received | Checkpointed | Cleared if no values are received in an update |
| `LastValue` | The last received value | Raises error if more than one value is received | Checkpointed | Overwritten by new value; not explicitly cleared |
| `LastValueAfterFinish` | The last received value, made available after `finish()` | Stores the last value received | Checkpointed as a tuple `(value, finished_status)` | Cleared after `consume()` is called and `finished` is `True` |
| `EphemeralValue` | The value from the immediately preceding step | Raises error if `guard=True` and multiple values are received | Checkpointed (stores current value) | Cleared if no values are received in an update |
| `UntrackedValue` | The last received value | Raises error if `guard=True` and multiple values are received | Never checkpointed (always `MISSING` in checkpoint) | Overwritten by new value; not explicitly cleared |
| `BinaryOperatorAggregate` | The result of applying a binary operator | Aggregates values using the defined operator | Checkpointed | Aggregated using the `operator`; can be overwritten |
| `Topic` | A sequence of values | Flattens and extends the list of values | Checkpointed as a list of values | Cleared if `accumulate` is `False` at the start of an update |

LangGraph employs a modular channel system to manage mutable state within computational graphs, enabling dynamic data flow and persistence. At its foundation, the [`BaseChannel`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/channels/base.py#L19) abstract class, defined in /langchain-ai/langgraph/libs/langgraph/langgraph/channels/base.py, establishes a common interface for all channel types. This interface specifies methods for updating, retrieving, checkpointing, and restoring channel values, ensuring consistency across diverse state management strategies. Channels are generic, allowing for type-safe handling of various data structures, and use [`__slots__`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L315) for memory efficiency.

Several concrete implementations extend [`BaseChannel`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/channels/base.py#L19) to cater to different state management requirements:

- **[`AnyValue`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/channels/any_value.py#L15)**: Located in /langchain-ai/langgraph/libs/langgraph/langgraph/channels/any\_value.py, this channel stores a single value. It assumes that multiple updates within a step conceptually represent the same value, retaining only the last one.
- **[`LastValue`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/channels/last_value.py#L20)**: Defined in /langchain-ai/langgraph/libs/langgraph/langgraph/channels/last\_value.py, this channel strictly stores the most recently received single value, raising an error if multiple updates are attempted within one step.
- **[`EphemeralValue`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/channels/ephemeral_value.py#L15)**: In /langchain-ai/langgraph/libs/langgraph/langgraph/channels/ephemeral\_value.py, this channel holds the most recent value for a single step. If no new value is provided in the subsequent step, the stored value is cleared, ensuring transience. It includes an optional [`guard`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/concepts/auth.md?plain=1#L470) mechanism to prevent multiple updates within a single step.
- **[`UntrackedValue`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/channels/untracked_value.py#L15)**: This channel, found in /langchain-ai/langgraph/libs/langgraph/langgraph/channels/untracked\_value.py, stores the last received value but explicitly opts out of checkpointing, making its state non-persistent across runs.
- **[`BinaryOperatorAggregate`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/channels/binop.py#L41)**: In /langchain-ai/langgraph/libs/langgraph/langgraph/channels/binop.py, this channel aggregates incoming values using a specified binary operator (e.g., summation, merging dictionaries). It supports continuous accumulation or a complete overwrite of the accumulated value.
- **[`Topic`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/channels/topic.py#L23)**: Located in /langchain-ai/langgraph/libs/langgraph/langgraph/channels/topic.py, this channel functions like a PubSub system, managing a sequence of values. It can be configured to either accumulate values across multiple steps or clear them on each update, flattening incoming sequences.

Additionally, channels such as [`LastValueAfterFinish`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/channels/last_value.py#L81) and [`NamedBarrierValue`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/channels/named_barrier_value.py#L13) (both in /langchain-ai/langgraph/libs/langgraph/langgraph/channels/last\_value.py and /langchain-ai/langgraph/libs/langgraph/langgraph/channels/named\_barrier\_value.py respectively) offer specialized behaviors, such as delaying value availability until an explicit [`finish()`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_algo.py#L315) call or until a specific set of named values has been received. This comprehensive system allows for intricate state management patterns, crucial for orchestrating complex agent behaviors and ensuring data integrity and flow within LangGraph's Pregel-inspired execution model. For further details on how these channels integrate with execution, refer to [Pregel Execution Model and Graph Orchestration](https://codewiki.google/github.com/langchain-ai/langgraph#langgraph-core-framework-pregel-execution-model-and-graph-orchestration). The mechanism for storing and retrieving these channel states is elaborated in [Checkpoint Saving and Retrieval](https://codewiki.google/github.com/langchain-ai/langgraph#persistence-and-checkpointing-checkpoint-saving-and-retrieval).

### Functional API and Runtime Configuration

link

zoom\_in

LangGraph's functional API provides decorators that transform Python functions into executable units within a graph, enabling definition of computational tasks and entire workflow entrypoints with built-in mechanisms for fault tolerance and performance optimization.

The [`@task`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/llms.txt#L51) decorator, defined in [`libs/langgraph/langgraph/func/__init__.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/func/__init__.py), allows a Python function to be registered as an independent computational unit. These tasks can be executed in parallel and support [`retry_policy`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/main.py#L612) for handling transient failures and [`cache_policy`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/main.py#L615) for caching results, leveraging a [`BaseCache`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/base/__init__.py#L15) for improved performance. When called from an entrypoint or a [`StateGraph`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/state.py#L111), [`@task`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/llms.txt#L51) functions return objects that facilitate asynchronous waiting, enabling parallel execution.

For orchestrating complete workflows, the [`@entrypoint`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/llms.txt#L51) decorator, also found in [`libs/langgraph/langgraph/func/__init__.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/func/__init__.py), converts a standard Python function into a [`Pregel`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/main.py#L321) instance. This [`Pregel`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/main.py#L321) instance forms the core execution engine of LangGraph, managing state, integrating with checkpointers for persistence, and handling input/output channels. An [`entrypoint`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/func/__init__.py#L228) can specify a [`retry_policy`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/main.py#L612) and [`cache_policy`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/main.py#L615) that apply to the entire workflow. It also facilitates sophisticated state management through [`entrypoint.final`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/concepts/functional_api.md?plain=1#L742), which allows distinguishing between the value returned to the caller and the value saved to the checkpointer for subsequent invocations.

At runtime, LangGraph propagates contextual information and manages resources through various utilities. [`RunnableConfig`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/agents/agents.md?plain=1#L224), [`BaseStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L700), and [`StreamWriter`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L92) provide mechanisms for accessing and managing this context. For instance, [`get_config`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/config.py#L17) retrieves the current [`RunnableConfig`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/agents/agents.md?plain=1#L224), [`get_store`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/config.py#L32) provides access to the persistent [`BaseStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L700), and [`get_stream_writer`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/config.py#L126) allows writing real-time updates to a [`StreamWriter`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L92). These utilities enable dynamic configuration, state persistence, and real-time output throughout the execution of a LangGraph workflow.

### Dynamic Control Flow and Commands

link

zoom\_in

LangGraph provides mechanisms for dynamically altering the execution path of a graph and for controlling the graph's state and flow from within its nodes.

Conditional routing in LangGraph is managed through the [`BranchSpec`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/_branch.py#L83) named tuple, defined in /langchain-ai/langgraph/libs/langgraph/langgraph/graph/\_branch.py. A [`BranchSpec`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/_branch.py#L83) encapsulates the logic for determining the next node(s) in a graph based on an input. It utilizes a [`Runnable`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/tests/model.py#L15) or a callable as its [`path`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_algo.py#L93) property, which processes the current state or input and returns a hashable value or a list of hashable values. These outputs are then mapped to specific node names within the graph via the [`ends`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/_node.py#L91) property, allowing the graph to execute different branches of logic based on dynamic conditions. This enables flexible workflows where the next step is not predetermined but depends on the outcome of a prior computation.

For more complex control over graph execution, LangGraph introduces [`Command`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L349) objects, which are defined in /langchain-ai/langgraph/libs/langgraph/langgraph/types.py. These commands enable nodes to issue instructions to the graph's execution engine, facilitating features like human-in-the-loop interactions and advanced state manipulation. Key [`Command`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L349) types include:

- **[`update`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L921)**: Modifies the graph's state by applying specified changes.
- **[`resume`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L373)**: Continues execution from a previously interrupted state.
- **[`goto`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L374)**: Directs the graph to execute a specific node next, allowing for arbitrary jumps within the workflow.
- **[`interrupt`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L142)**: Pauses the graph's execution, surfacing a value to the client, and enabling human intervention. When a node calls [`interrupt`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L142) (also defined in /langchain-ai/langgraph/libs/langgraph/langgraph/types.py), the graph execution halts, awaiting external input to [`resume`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L373). Subsequent calls within the same task will return the resumed value. This functionality requires an enabled checkpointing system to store the graph's state during the pause. See [Persistence and Checkpointing](https://codewiki.google/github.com/langchain-ai/langgraph#persistence-and-checkpointing) for more details.

Additionally, the [`Send`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L270) class, found in /langchain-ai/langgraph/libs/langgraph/langgraph/types.py, allows for dynamic invocation of a node with a custom state within conditional edges, supporting patterns such as map-reduce by enabling a node to dynamically send messages to other nodes with specific arguments. The [`Overwrite`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L528) class, also defined in /langchain-ai/langgraph/libs/langgraph/langgraph/types.py, provides a mechanism to bypass standard state reducers and directly assign a value to a channel, which is particularly useful for certain types of state management, such as with [`BinaryOperatorAggregate`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/channels/binop.py#L41) channels.

## Persistence and Checkpointing

link

zoom\_in

LangGraph manages state persistence for AI agents, which facilitates features such as human-in-the-loop interactions and maintaining memory across conversational turns. This persistence is achieved through checkpointing, serialization, and various storage mechanisms. LangGraph supports multiple storage backends, including in-memory, SQLite, and PostgreSQL, and provides functionalities for key-value and vector storage, batch operations, and Time-To-Live (TTL) management.

At the core of this system is the [`BaseCheckpointSaver`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/__init__.py#L111) interface, which defines how agent states are saved, retrieved, listed, and deleted. This interface supports both synchronous and asynchronous operations, allowing for flexible integration into different application architectures. Checkpoints capture a snapshot of the graph's state, along with metadata and intermediate writes, which are crucial for resuming execution or analyzing past interactions. The [`InMemorySaver`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/memory/__init__.py#L31) is a basic implementation suitable for testing and development, storing all state within the application's memory. See [Checkpoint Saving and Retrieval](https://codewiki.google/github.com/langchain-ai/langgraph#persistence-and-checkpointing-checkpoint-saving-and-retrieval) for more details.

Serialization and deserialization are critical components for persisting complex Python objects. The framework employs [`JsonPlusSerializer`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py#L41), which efficiently handles various data types, including Pydantic models and NumPy arrays, and incorporates security measures to prevent arbitrary code execution during deserialization. For sensitive data, [`EncryptedSerializer`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/serde/encrypted.py#L8) provides encryption capabilities, wrapping a cipher protocol around the serialization process to ensure data security at rest. See [Serialization, Deserialization, and Encryption](https://codewiki.google/github.com/langchain-ai/langgraph#persistence-and-checkpointing-serialization-deserialization-and-encryption) for more details.

Beyond in-memory solutions, LangGraph provides robust persistence options using SQLite and PostgreSQL. The SQLite backend offers a local, durable storage solution for checkpoints, general key-value data, and cache entries. It supports vector search capabilities and TTL management, making it suitable for standalone applications or environments where a lightweight, embedded database is preferred. See [SQLite Persistence Backend](https://codewiki.google/github.com/langchain-ai/langgraph#persistence-and-checkpointing-sqlite-persistence-backend) for more details. For scalable and robust deployments, the PostgreSQL backend is available, offering similar functionalities for checkpoint saving, key-value storage, and caching, with advanced features like [`pgvector`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/docker.py#L181) for semantic search and comprehensive TTL management. See [PostgreSQL Persistence Backend](https://codewiki.google/github.com/langchain-ai/langgraph#persistence-and-checkpointing-postgresql-persistence-backend) for more details.

The system also includes a flexible caching framework, built around the [`BaseCache`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/base/__init__.py#L15) interface, with implementations like [`InMemoryCache`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/memory/__init__.py#L11) and [`RedisCache`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/redis/__init__.py#L10). These caches provide temporary storage for frequently accessed data, supporting configurable TTL policies and namespace isolation to optimize performance and manage data lifecycle. See [Caching Mechanisms](https://codewiki.google/github.com/langchain-ai/langgraph#persistence-and-checkpointing-caching-mechanisms) for more details.

A generic key-value store, defined by the [`BaseStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L700) interface, allows for flexible data storage with support for hierarchical namespaces, batch operations, structured filtering, and integrated vector search. This enables semantic queries on stored data by leveraging embeddings and configurable indexing. This generalized store is implemented by both the SQLite and PostgreSQL backends, providing a consistent API for diverse storage needs. See [Generic Key-Value Store with Vector Search](https://codewiki.google/github.com/langchain-ai/langgraph#persistence-and-checkpointing-generic-key-value-store-with-vector-search) for more details.

### Checkpoint Saving and Retrieval

link

zoom\_in

The LangGraph framework provides robust mechanisms for managing the mutable state of AI agents through checkpointing. This system allows for saving, retrieving, and listing the graph's state at various points, enabling features like human-in-the-loop interactions, fault tolerance, and conversational memory across multiple turns.

The core abstraction for persistence is the [`BaseCheckpointSaver`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/__init__.py#L111) interface, defined in [`libs/checkpoint/langgraph/checkpoint/base/__init__.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/__init__.py). This abstract class establishes a standard API for how checkpoints are interacted with, ensuring that different storage backends can be plugged into the LangGraph system seamlessly. It defines methods for common operations:

- **Saving**: The [`put`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L339) and [`aput`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/batch.py#L131) methods allow for storing a [`Checkpoint`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py#L172) object, which encapsulates the agent's full state, including channel values and versioning information. This enables capturing a snapshot of the graph's execution at any given moment.
- **Retrieval**: [`get`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L299) and [`aget`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/batch.py#L82) retrieve a specific [`Checkpoint`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py#L172) based on configuration, while [`get_tuple`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/tests/memory_assert.py#L38) and [`aget_tuple`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/__init__.py#L259) provide a more comprehensive [`CheckpointTuple`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/__init__.py#L101) that includes metadata and parent information. This allows the graph to be rehydrated to a previous state.
- **Listing**: The [`list`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L2553) and [`alist`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/__init__.py#L273) methods enable querying and retrieving multiple [`CheckpointTuple`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/__init__.py#L101) instances based on filters, facilitating historical analysis or iteration over various agent states.
- **Deletion**: [`delete_thread`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/__init__.py#L236) and [`adelete_thread`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/__init__.py#L341) provide functionality to remove all checkpoints associated with a particular agent thread, useful for managing storage and privacy.

A [`Checkpoint`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py#L172) itself is a [`TypedDict`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/agents/agents.md?plain=1#L384) containing details such as its unique [`id`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/mkdocs.yml#L201), timestamp ( [`ts`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/AGENTS.md?plain=1#L30)), the actual [`channel_values`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/README.md?plain=1#L59) (deserialized state for each channel), [`channel_versions`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/README.md?plain=1#L63) to track changes, and [`versions_seen`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/README.md?plain=1#L69) which indicates which nodes have processed specific channel versions. Each checkpoint can also include [`CheckpointMetadata`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/__init__.py#L31), providing context like its [`source`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/README.md?plain=1#L2) (e.g., [`"input"`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/bench/wide_dict.py#L133), [`"loop"`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/CONTRIBUTING.md?plain=1#L75)) and the [`step`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/README.md?plain=1#L14) number within the graph execution.

The system also manages intermediate writes and large channel values. When a checkpoint is saved, [`new_versions`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/tests/memory_assert.py#L38) of channels might be stored as separate "blobs" to optimize storage and retrieval. This is evident in the [`InMemorySaver`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/memory/__init__.py#L31), located at [`libs/checkpoint/langgraph/checkpoint/memory/__init__.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/memory/__init__.py), which uses distinct dictionaries for [`storage`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/reference/store.md?plain=1#L1), [`writes`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_algo.py#L99), and [`blobs`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/cloud/reference/langgraph_server_changelog.md?plain=1#L71). Although [`InMemorySaver`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/memory/__init__.py#L31) is primarily for testing and debugging, it demonstrates how channel values can be handled separately from the core checkpoint structure, providing an example of a concrete [`BaseCheckpointSaver`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/__init__.py#L111) implementation.

To ensure data integrity and efficient storage, serialization is a critical component. The [`BaseCheckpointSaver`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/__init__.py#L111) relies on a [`SerializerProtocol`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/serde/base.py#L15), typically implemented by [`JsonPlusSerializer`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py#L41), to convert complex Python objects into a storable byte-string format. This serialization process is also capable of being secured through encryption, as described in [Serialization, Deserialization, and Encryption](https://codewiki.google/github.com/langchain-ai/langgraph#persistence-and-checkpointing-serialization-deserialization-and-encryption).

Version management for channels is also integral. The [`BaseCheckpointSaver`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/__init__.py#L111) includes a [`get_next_version`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/__init__.py#L352) method, which can be overridden, to generate monotonically increasing version IDs for channel updates, ensuring a clear lineage of state changes. Furthermore, the use of [`UUIDv6`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/id.py#L81) for checkpoint IDs, generated by [`libs/checkpoint/langgraph/checkpoint/base/id.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/id.py), provides time-ordered identifiers that are beneficial for database indexing and maintaining chronological order of checkpoints.

### Serialization, Deserialization, and Encryption

link

zoom\_in

LangGraph utilizes a robust serialization and deserialization framework for managing complex Python objects, which is critical for checkpointing and state persistence. This framework includes mechanisms for efficient data conversion and secure handling of sensitive information through encryption.

At its core, the serialization process is managed by [`JsonPlusSerializer`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py#L41) located in [`libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py). This serializer is designed to convert a wide range of Python objects into a byte-string format, primarily leveraging [`ormsgpack`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/pyproject.toml#L16) for performance. It handles various built-in types, including Pydantic models, [`pathlib.Path`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/cli.py#L34) objects, [`UUID`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/id.py#L15) s, [`datetime`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py#L6) objects, and [`numpy`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/pyproject.toml#L71) arrays, by mapping them to [`ormsgpack.Ext`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py#L222) objects which embed type and constructor information. A key feature of [`JsonPlusSerializer`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py#L41) is its security mechanism: [`allowed_json_modules`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/schemas/schema.json#L505). This parameter restricts the modules and classes that can be deserialized from their constructor representation, mitigating the risk of arbitrary code execution when processing data from untrusted sources. While it offers a [`pickle_fallback`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/schemas/schema.json#L525) option for types not natively supported, this is generally discouraged due to security implications.

For sensitive data, LangGraph provides the [`EncryptedSerializer`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/serde/encrypted.py#L8) (defined in [`libs/checkpoint/langgraph/checkpoint/serde/encrypted.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/serde/encrypted.py)). This serializer wraps another serializer, typically [`JsonPlusSerializer`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/serde/jsonplus.py#L41), and encrypts the serialized data using a specified [`CipherProtocol`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/serde/base.py#L53). The [`EncryptedSerializer`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/serde/encrypted.py#L8) allows for secure storage or transmission of agent states by encrypting the bytes before storage and decrypting them upon retrieval. An example implementation uses AES encryption via [`pycryptodome`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/pyproject.toml#L66) for authenticated encryption, ensuring both confidentiality and integrity of the data. This setup ensures that state data, which might contain proprietary or personal information, remains protected when persisted.

The foundational interfaces for these operations are defined in [`base.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/_scripts/notebook_convert.py#L332) within the [`serde`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/base/__init__.py#L125) directory, including [`SerializerProtocol`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/serde/base.py#L15) for typed serialization and [`CipherProtocol`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/serde/base.py#L53) for encryption. These protocols ensure that different serialization and encryption implementations can be seamlessly integrated. The overall checkpointing system, which heavily relies on these serialization capabilities, is discussed further in [Checkpoint Saving and Retrieval](https://codewiki.google/github.com/langchain-ai/langgraph#persistence-and-checkpointing-checkpoint-saving-and-retrieval).

### In-Memory Persistence Backends

link

| Backend Name | Primary Purpose | Key Features | Typical Use Cases |
| --- | --- | --- | --- |
| `InMemorySaver` | Stores checkpoints for stateful graph execution. | Stores full graph state, thread-safe, uses `defaultdict` internally. | Debugging, testing, simple single-process applications without persistence needs. |
| `InMemoryCache` | Caching of key-value pairs with optional time-to-live (TTL). | Thread-safe, supports TTL for cached items, uses `dict` with `RLock`. | Caching intermediate results, reducing redundant computations, quick lookups. |
| `InMemoryStore` | Generic key-value storage with optional vector search capabilities. | Thread-safe, supports vector embeddings and similarity search, `defaultdict` for namespaces, integrates with LangChain embeddings. | Storing structured data, semantic search on documents, RAG applications (for small datasets). |

LangGraph provides in-memory implementations for state persistence, primarily for scenarios where data does not need to outlive the current process. These backends are suited for development, testing, and use cases where rapid, transient storage is sufficient. This includes in-memory checkpoint saving, key-value storage, and caching mechanisms.

For managing the state of a graph, [`InMemorySaver`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/memory/__init__.py#L31) within [`libs/checkpoint/langgraph/checkpoint/memory`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/checkpoint/memory) offers an ephemeral checkpointing solution. It stores serialized checkpoint data, metadata, and channel values directly in memory. This saver provides both synchronous and asynchronous interfaces for saving, retrieving, and listing graph states, as well as managing associated writes and blobs. It supports the serialization and deserialization of checkpoint data, mimicking persistent storage behavior for consistent data handling without actual disk writes. This approach is beneficial for quickly iterating on graph designs and verifying agent behavior without the overhead of disk I/O.

In addition to checkpointing, an [`InMemoryCache`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/memory/__init__.py#L11) implemented in [`libs/checkpoint/langgraph/cache/memory`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/memory) facilitates thread-safe storage and retrieval of frequently accessed data. This cache supports optional Time-to-Live (TTL) expiration, automatically removing stale entries to ensure data freshness. Serialization and deserialization protocols are used to store Python objects as byte formats, enabling the caching of various data types. The cache is optimized for concurrent access, allowing multiple readers while ensuring exclusive access for writes, which is typical for performance-critical caching needs.

For general-purpose key-value storage, [`InMemoryStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/memory/__init__.py#L136) in [`libs/checkpoint/langgraph/store/memory`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/memory) provides a dictionary-backed solution. This store supports hierarchical namespaces and batch operations for efficient data management. Notably, it can be optionally configured with vector search capabilities. When enabled, it allows embedding text content from stored items and performing similarity searches based on these embeddings, enhancing retrieval for relevant data. The store prioritizes speed by keeping all data in memory, making it a suitable choice for data that does not require long-term persistence but benefits from fast access and potential vector-based retrieval.

### SQLite Persistence Backend

link

zoom\_in

SQLite offers a robust and local solution for persisting LangGraph application states. It supports durable storage for [`CheckpointSaver`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-sqlite/README.md?plain=1#L3), a generic [`BaseStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L700) for key-value data, and a [`BaseCache`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/base/__init__.py#L15) for temporary storage. Implementations are available for both synchronous and asynchronous operations, catering to various application needs.

For checkpointing, LangGraph provides [`SqliteSaver`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/__init__.py#L38) and [`AsyncSqliteSaver`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/aio.py#L30) in the [`libs/checkpoint-sqlite/langgraph/checkpoint/sqlite`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-sqlite/langgraph/checkpoint/sqlite) directory. These classes manage the saving, retrieval, listing, and deletion of graph states and intermediate channel writes using an SQLite database. They ensure thread safety in synchronous contexts via [`threading.Lock`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_algo.py#L1196) and non-blocking I/O in asynchronous contexts through [`aiosqlite`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-sqlite/README.md?plain=1#L3) and [`asyncio.Lock`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-sqlite/langgraph/store/sqlite/aio.py#L109), respectively. Checkpoints are stored in [`checkpoints`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/concepts/persistence.md?plain=1#L44) and [`writes`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/_algo.py#L99) tables, allowing for detailed tracking of state evolution and channel updates.

The persistence of general key-value data is handled by [`SqliteStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-sqlite/langgraph/store/sqlite/base.py#L724) and [`AsyncSqliteStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-sqlite/langgraph/store/sqlite/aio.py#L39), located in [`libs/checkpoint-sqlite/langgraph/store/sqlite`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-sqlite/langgraph/store/sqlite). These stores support batch operations, Time-To-Live (TTL) for automatic data expiration, and vector search capabilities when configured with [`SqliteIndexConfig`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-sqlite/langgraph/store/sqlite/base.py#L90). Vector search uses embeddings to enable semantic queries, leveraging the [`sqlite_vec`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-sqlite/langgraph/store/sqlite/aio.py#L13) extension for efficient similarity calculations. TTL is managed through [`expires_at`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-sqlite/langgraph/store/sqlite/aio.py#L249) timestamps, with background sweepers for cleanup and an option to refresh TTL on read.

A persistent caching mechanism is implemented by [`SqliteCache`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-sqlite/langgraph/cache/sqlite/__init__.py#L13) within [`libs/checkpoint-sqlite/langgraph/cache/sqlite`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-sqlite/langgraph/cache/sqlite). This cache provides key-value storage with optional expiration, namespace management for logical data grouping, and flexible serialization of Python objects. It supports both synchronous and asynchronous access, with [`threading.RLock`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/memory/__init__.py#L15) ensuring thread safety for concurrent operations.

### PostgreSQL Persistence Backend

link

zoom\_in

LangGraph provides a robust integration with PostgreSQL for persisting the state of AI agents, offering both checkpointing and general-purpose key-value/vector storage. This enables features such as human-in-the-loop interactions and memory across conversational turns. The implementation supports both synchronous and asynchronous operations, catering to various application architectures.

The core of PostgreSQL persistence is realized through two main components: [`CheckpointSaver`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-sqlite/README.md?plain=1#L3) and [`BaseStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L700). The [`PostgresSaver`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py#L32) class and its asynchronous counterpart [`AsyncPostgresSaver`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-postgres/langgraph/checkpoint/postgres/aio.py#L32) are responsible for managing LangGraph's execution state. These savers store, retrieve, list, and delete agent checkpoints, including associated metadata and intermediate writes. They handle the separation of primitive and non-primitive channel values, storing the latter as serialized blobs. Database schema management is handled through migrations, ensuring compatibility as the data model evolves.

For general-purpose data management beyond checkpoints, LangGraph offers [`PostgresStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-postgres/langgraph/store/postgres/base.py#L629) and [`AsyncPostgresStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-postgres/langgraph/store/postgres/aio.py#L42). These classes provide a flexible key-value store with support for hierarchical namespaces, batch operations, and structured filtering. A key feature is the integration of [`pgvector`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/docker.py#L181), which enables semantic search capabilities by storing vector embeddings and performing similarity queries. This allows agents to retrieve contextually relevant information efficiently. Both [`PostgresStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint-postgres/langgraph/store/postgres/base.py#L629) implementations include Time-To-Live (TTL) management, which automatically handles the expiration and removal of data after a specified duration. The persistence layers leverage [`psycopg`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/pyproject.toml#L43) for database interaction, and [`orjson`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/pyproject.toml#L16) for efficient JSON serialization. Connection management can utilize direct connections or connection pools for scalability.

For a detailed understanding of how checkpoints are saved and retrieved, refer to the [Checkpoint Saving and Retrieval](https://codewiki.google/github.com/langchain-ai/langgraph#persistence-and-checkpointing-checkpoint-saving-and-retrieval) section. The [Serialization, Deserialization, and Encryption](https://codewiki.google/github.com/langchain-ai/langgraph#persistence-and-checkpointing-serialization-deserialization-and-encryption) section provides further context on data handling, and the [Generic Key-Value Store with Vector Search](https://codewiki.google/github.com/langchain-ai/langgraph#persistence-and-checkpointing-generic-key-value-store-with-vector-search) section elaborates on the [`BaseStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L700) interface.

### Caching Mechanisms

link

zoom\_in

LangGraph's caching framework provides mechanisms for temporary storage of frequently accessed data, supporting both in-memory and Redis backends with Time-To-Live (TTL) management. The core of this system is the [`BaseCache`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/base/__init__.py#L15) interface, which defines synchronous and asynchronous operations for storing, retrieving, and clearing cached values. This interface ensures consistency across different caching implementations and handles serialization and deserialization of Python objects, including a [`pickle_fallback`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/schemas/schema.json#L525) for complex types.

Implementations of [`BaseCache`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/base/__init__.py#L15) include [`InMemoryCache`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/memory/__init__.py#L11) and [`RedisCache`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/redis/__init__.py#L10). [`InMemoryCache`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/memory/__init__.py#L11) provides a thread-safe, volatile storage solution using an internal Python dictionary. It automatically handles TTL expiration during retrieval and ensures safe concurrent access through re-entrant locks. The [`RedisCache`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/redis/__init__.py#L10) offers a persistent and distributed caching solution that leverages a Redis instance. It constructs unique Redis keys using a configurable prefix and namespace, optimizes performance through batch operations like [`mget`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/redis/__init__.py#L60) and pipelines, and manages TTL directly within Redis. Both implementations provide asynchronous APIs, though for [`InMemoryCache`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/memory/__init__.py#L11), these wrap synchronous operations, while for [`RedisCache`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/cache/redis/__init__.py#L10), they serve as placeholders for future native asynchronous Redis client integration.

### Generic Key-Value Store with Vector Search

link

zoom\_in

LangGraph provides a flexible generic key-value store, defined by the [`BaseStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L700) interface in [`libs/checkpoint/langgraph/store/base/__init__.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py). This interface supports hierarchical namespaces, efficient batch operations, structured filtering, and integrated vector search capabilities.

The core of the system is the [`BaseStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L700) abstract base class, which outlines the contract for all persistent storage implementations. It includes methods for storing, retrieving, and searching [`Item`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py#L456) objects, which consist of a value, key, and a hierarchical namespace. All fundamental read and write operations are processed via [`batch`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/batch.py#L190) and [`abatch`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L737) methods, promoting efficient, batched interactions with the underlying storage.

The store offers robust search capabilities. Users can retrieve items based on [`namespace_prefix`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L3319), apply structured filters using operators like [`$eq`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/concepts/auth.md?plain=1#L548) and [`$gt`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L274), and leverage pagination for managing large result sets. For more advanced querying, the [`SearchOp`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L203) within [`BaseStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L700) supports natural language [`query`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L293) parameters, enabling semantic search through integrated vector search. This is facilitated by [`IndexConfig`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/schemas.py#L31), which allows specifying embedding models and identifying fields within stored items for vector indexing.

Dynamic management of data lifecycle is supported through Time-to-Live (TTL) functionality, configurable via [`ttl`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L133) in [`PutOp`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L431) and [`TTLConfig`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/schemas.py#L7) for automatic item expiration. Store implementations can indicate their support for TTL through the [`supports_ttl`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L719) attribute. Namespaces themselves can be explored and filtered using [`list_namespaces`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/types.py#L1089), supporting prefix and suffix matching for navigation.

For in-memory scenarios, LangGraph provides an [`InMemoryStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/memory/__init__.py#L136) implementation in [`libs/checkpoint/langgraph/store/memory/__init__.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/memory/__init__.py). This implementation is dictionary-backed, offering fast but non-persistent storage. It fully supports the vector search capabilities defined by [`BaseStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L700), utilizing [`index`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/tests/model.py#L25) configurations to embed text content from stored items and perform similarity searches. This in-memory store leverages optimized cosine similarity calculations, conditionally using [`numpy`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/pyproject.toml#L71) for enhanced performance.

The system further includes an [`AsyncBatchedBaseStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/batch.py#L58) wrapper in [`libs/checkpoint/langgraph/store/base/batch.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/batch.py), which enables efficient batching of asynchronous operations using a background task. This design minimizes contention and optimizes performance by allowing the underlying [`BaseStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L700) to process multiple operations in a single batch.

Embedding functions, which are crucial for vector search, are managed and adapted through utilities in [`libs/checkpoint/langgraph/store/base/embed.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/embed.py). This module provides [`ensure_embeddings`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/embed.py#L34) to convert various inputs—including existing [`Embeddings`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/tests/embed_test_utils.py#L8) objects, custom callables, or string identifiers for external providers—into a compatible [`Embeddings`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/tests/embed_test_utils.py#L8) instance. The [`EmbeddingsLambda`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/embed.py#L109) class acts as an adapter, allowing custom synchronous or asynchronous embedding functions to conform to the [`Embeddings`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/tests/embed_test_utils.py#L8) interface. Text content for embedding can be precisely extracted from complex Python objects using path expressions via [`get_text_at_path`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/embed.py#L233).

### Agent Creation and Orchestration (create\_react\_agent)

link

zoom\_in

The primary mechanism for constructing conversational AI agents in LangGraph is the [`create_react_agent`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py#L273) function, defined in \[/langchain-ai/langgraph/libs/prebuilt/langgraph/prebuilt/chat\_agent\_executor.py\]. This function assembles a [Graph Definition and Compilation](https://codewiki.google/github.com/langchain-ai/langgraph#langgraph-core-framework-graph-definition-and-compilation) instance, specifically a [`CompiledStateGraph`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/state.py#L912), to orchestrate a ReAct (Reasoning and Acting) loop. This loop enables agents to interact with large language models, process their responses, and dynamically execute external tools.

The agent's workflow, managed by the [`CompiledStateGraph`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/state.py#L912), involves calling a [`BaseChatModel`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/agents/models.md?plain=1#L67) instance with a history of messages. If the model's response ( [`AIMessage`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/README.md?plain=1#L46)) includes tool calls, these are dispatched for execution by a [Robust Tool Execution (ToolNode)](https://codewiki.google/github.com/langchain-ai/langgraph#prebuilt-agent-components-robust-tool-execution-toolnode). The results of these tool calls are then added back to the message history, and the language model is invoked again, forming an iterative process until a stopping condition is met.

[`create_react_agent`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py#L273) supports dynamic model selection, allowing the choice of the [`BaseChatModel`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/agents/models.md?plain=1#L67) to be determined at runtime based on the agent's current state and context. It also integrates custom logic through [`pre_model_hook`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/tests/test_react_agent.py#L1943) and [`post_model_hook`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/tests/test_react_agent.py#L1978) functions or runnables. These hooks provide interception points to modify the agent's state before or after the language model interaction, enabling capabilities such as message trimming or human-in-the-loop interventions. For scenarios requiring structured machine-readable outputs, the function can be configured to generate a final structured response after the agent loop concludes.

The conversational state is primarily maintained as a sequence of [`BaseMessage`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/agents/context.md?plain=1#L198) objects, with [`AgentState`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/examples/graphs/agent.py#L25) defining the schema for this state. The underlying framework leverages [`langchain_core.runnables`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/agents/agents.md?plain=1#L224) for composability and supports both synchronous and asynchronous execution paths. Further details on data structures can be found in [Data Models and Schema Definition](https://codewiki.google/github.com/langchain-ai/langgraph#python-sdk-for-langgraph-data-models-and-schema-definition).

It can execute multiple tools concurrently, which is beneficial for efficiency in scenarios requiring several external calls.

Error handling is a configurable aspect of [`ToolNode`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/tool_node.py#L535) through the [`handle_tool_errors`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/how-tos/tool-calling.md?plain=1#L367) parameter. This allows developers to define how tool execution failures are managed, ranging from custom error message generation to selective exception catching, providing flexibility in how agents respond to tool malfunctions.

For enhanced tool functionality, [`ToolNode`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/tool_node.py#L535) automatically injects relevant graph state and runtime information. Arguments annotated with [`InjectedState`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/tool_node.py#L1540) receive specific portions of the graph's current state, while [`InjectedStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/tool_node.py#L1616) provides access to a persistent [`BaseStore`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/checkpoint/langgraph/store/base/__init__.py#L700) instance. The [`ToolRuntime`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/tool_node.py#L1481) annotation allows tools to access comprehensive runtime context, including configuration and stream writers. This injection mechanism simplifies tool development by making contextual data readily available without explicit passing by the language model.

Custom logic can be integrated into the tool execution flow using [`wrap_tool_call`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/tool_node.py#L192) and [`awrap_tool_call`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/tool_node.py#L661). These synchronous and asynchronous wrappers intercept tool calls, enabling modifications to arguments, short-circuiting of execution, or custom error handling before and after the tool is invoked. Tools can also influence the graph's control flow by returning [`Command`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/types.py#L349) objects, which can trigger state updates, graph navigation, or message sending within the LangGraph.

The utility function [`tools_condition`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/tool_node.py#L1400) assists in conditional routing within the graph. It determines whether the last [`AIMessage`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/README.md?plain=1#L46) in the state contains tool calls, directing the graph's execution accordingly, typically to the [`ToolNode`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/tool_node.py#L535) for execution or to an end state if no tools are required. For details on how these prebuilt components are used to construct agents, refer to [Agent Creation and Orchestration (create\_react\_agent)](https://codewiki.google/github.com/langchain-ai/langgraph#prebuilt-agent-components-agent-creation-and-orchestration-create-react-agent).

### Input Validation (ValidationNode)

link

zoom\_in

The [`ValidationNode`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/tool_validator.py#L47) class provides a mechanism within LangGraph for validating [`ToolCall`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/concepts/tools.md?plain=1#L29) arguments against predefined Pydantic schemas. This node functions as a [`RunnableCallable`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/_internal/_runnable.py#L254), meaning it can be integrated into computational graphs to process inputs and produce outputs. Its primary role is to intercept and scrutinize [`ToolCall`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/concepts/tools.md?plain=1#L29) objects, typically extracted from an [`AIMessage`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/README.md?plain=1#L46) in an agent's conversational state, to ensure that the arguments intended for a tool adhere to their expected data structures.

Upon receiving a [`ToolCall`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/concepts/tools.md?plain=1#L29), the [`ValidationNode`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/tool_validator.py#L47) attempts to validate its arguments against the corresponding Pydantic schema associated with the tool. If validation is successful, it generates a [`ToolMessage`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/how-tos/graph-api.md?plain=1#L3050) containing the validated and correctly formatted arguments. If validation fails, for instance due to type mismatches or missing required fields, the node produces a [`ToolMessage`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/how-tos/graph-api.md?plain=1#L3050) with an informative error message. This error message can then be fed back into the agent's workflow, allowing the language model to receive structured feedback and attempt to correct its [`ToolCall`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/concepts/tools.md?plain=1#L29) in a subsequent turn. This process facilitates the re-prompting of models for corrected tool calls without necessarily halting the overall agent execution.

It is important to note that [`ValidationNode`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/tool_validator.py#L47) is in a deprecated state. The framework is moving towards integrating validation and error handling directly into agent creation processes, as indicated by its deprecation in favor of more generalized mechanisms within [`langchain.agents`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/interrupt.py#L8). This suggests a design evolution where argument validation becomes a more intrinsic part of the tool execution or agent construction logic, rather than a standalone graph node. For a broader understanding of agent creation and orchestration, refer to [Agent Creation and Orchestration (create\_react\_agent)](https://codewiki.google/github.com/langchain-ai/langgraph#prebuilt-agent-components-agent-creation-and-orchestration-create-react-agent).

### Human Interruption Handling

link

zoom\_in

LangGraph provides data structures to manage human intervention within a graph's execution flow, particularly for agent-based systems. These structures facilitate pausing a graph, requesting specific human actions, and interpreting human responses to resume execution. The primary data structures involved are [`HumanInterruptConfig`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/interrupt.py#L11), [`ActionRequest`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/interrupt.py#L33), [`HumanInterrupt`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/interrupt.py#L51), and [`HumanResponse`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/interrupt.py#L87), all defined in [/langchain-ai/langgraph/libs/prebuilt/langgraph/prebuilt/interrupt.py](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/interrupt.py).

[`HumanInterruptConfig`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/interrupt.py#L11) specifies the actions a human is permitted to take when an interrupt occurs, such as allowing them to ignore, respond, edit, or accept a state. An [`ActionRequest`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/interrupt.py#L33) represents a specific action requested from a human, detailing the action type and any necessary arguments. These two are combined in a [`HumanInterrupt`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/interrupt.py#L51) object, which encapsulates a full request to pause execution and seek human input. For example, a [`HumanInterrupt`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/interrupt.py#L51) can be used to request a human review a command before it is executed, specifying options for the human to ignore, respond to, or accept the proposed action.

Conversely, a [`HumanResponse`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/interrupt.py#L87) represents the feedback provided by a human after an interrupt, indicating whether they accepted, ignored, responded to, or edited the proposed action, along with any associated arguments. This response is then used to guide the graph's continued execution. Most of these structures, with the exception of [`HumanResponse`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/interrupt.py#L87), are marked as deprecated, indicating a transition towards [`langchain.agents.interrupt`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/langgraph/prebuilt/interrupt.py#L8) for centralized interrupt logic. For additional context on agent components, refer to [Prebuilt Agent Components](https://codewiki.google/github.com/langchain-ai/langgraph#prebuilt-agent-components).

## Command-Line Interface (CLI) and Development Tools

The [`langgraph_cli`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/mkdocs.yml#L111) provides a command-line interface for managing LangGraph applications, offering functionalities that span project initiation, local development, and Docker-based deployment. This CLI is designed to streamline the lifecycle of LangGraph applications, from conceptualization to execution.

For project creation, the [`langgraph new`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/README.md?plain=1#L1) command initializes new LangGraph projects using predefined templates, guiding users through an interactive selection process, as orchestrated by [`create_new`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/templates.py#L164) in [`libs/cli/langgraph_cli/templates.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/templates.py). During development, the [`langgraph dev`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/README.md?plain=1#L1) command runs an in-memory API server, providing hot-reloading capabilities. This allows developers to see changes reflected immediately without manual restarts, configurable via host, port, and debug options. The configuration for this server, and indeed for most CLI operations, relies on a [`langgraph.json`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/README.md?plain=1#L34) file, whose schema is generated by [`generate_schema.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/Makefile#L37) in [`libs/cli/generate_schema.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/generate_schema.py). This schema generation process incorporates docstrings for better IDE support and enforces mutual exclusivity between Python and Node.js specific configurations, ensuring robust validation.

For deployment, the CLI facilitates Docker-based operations. The [`langgraph up`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/Makefile#L5) command launches the LangGraph API server within a Docker container, dynamically generating Docker Compose files and handling port mapping. Similarly, [`langgraph build`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/README.md?plain=1#L61) constructs a Docker image for the application, and [`langgraph dockerfile`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/README.md?plain=1#L1) generates a [`Dockerfile`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/README.md?plain=1#L59) and optionally [`docker-compose.yml`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/cli.py#L28) and [`.env`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/schemas/schema.json#L114) files. These Docker-related commands abstract away much of the complexity of containerization, leveraging functions like [`config_to_docker`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/config.py#L1132) and [`compose_as_dict`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/docker.py#L138) within [`libs/cli/langgraph_cli/config.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/config.py) and [`libs/cli/langgraph_cli/docker.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/docker.py) respectively, to tailor Docker configurations to specific project needs, supporting both Python and Node.js environments.

The CLI also integrates with comprehensive example applications and development workflows. Python examples, located in [`libs/cli/examples`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/examples) and [`libs/cli/python-monorepo-example`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/python-monorepo-example), demonstrate various agent workflows, multi-agent systems, and monorepo structures. Similarly, JavaScript examples in [`libs/cli/js-examples`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/js-examples) and [`libs/cli/js-monorepo-example`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/js-monorepo-example) showcase LangGraph.js chatbots with persistent memory and monorepo integration. These examples serve as practical templates for diverse LangGraph applications. Development workflows are further automated through [`Makefile`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/Makefile#L24) targets, facilitating tasks such as testing, linting, and formatting.

In addition to core functionalities, the CLI incorporates anonymized command usage analytics, implemented in [`libs/cli/langgraph_cli/analytics.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/analytics.py). This feature collects telemetry data, helping to understand usage patterns while respecting user privacy through anonymization, with an opt-out mechanism. Robust utilities for executing external commands asynchronously and displaying progress indicators for long-running operations are also provided, enhancing the user experience.

This command assists users in configuring their projects for containerization without manual Dockerfile creation.

The CLI's design separates concerns by delegating Docker-specific logic to modules that handle Docker environment checks, Docker Compose configuration generation, and YAML serialization. Configuration parsing and validation are managed by a dedicated module that ensures adherence to defined schemas for Python and Node.js applications. Execution utilities manage external commands, such as Docker, ensuring robust process execution and signal handling. Progress indicators provide visual feedback during long-running operations. The CLI also includes anonymized usage analytics for telemetry purposes, which users can opt out of. For details on the configuration schema and its validation, refer to [Configuration Management and Schema Generation](https://codewiki.google/github.com/langchain-ai/langgraph#command-line-interface-cli-and-development-tools-configuration-management-and-schema-generation).

### Configuration Management and Schema Generation

The LangGraph CLI manages application configurations through a structured [`Config`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/schemas.py#L414) schema, facilitating the definition and validation of project settings for both Python and Node.js applications. Configuration validation is handled by functions like [`validate_config`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/config.py#L111) and [`validate_config_file`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/config.py#L257) in [`libs/cli/langgraph_cli/config.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/config.py), ensuring adherence to specified rules. The CLI dynamically generates [`Dockerfile`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/README.md?plain=1#L59) content and Docker Compose configurations from these validated settings. This includes handling language-specific dependencies and build processes, as demonstrated by [`python_config_to_docker`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/config.py#L768) and [`node_config_to_docker`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/config.py#L988) which generate appropriate Dockerfiles. ### Analytics and Execution Utilities

link

zoom\_in

The LangGraph Command-Line Interface (CLI) incorporates mechanisms for collecting anonymized command usage analytics, along with robust utilities for managing external command execution and providing user feedback.

Anonymized command usage analytics are gathered through the [`log_command`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/analytics.py#L79) decorator, which wraps CLI functions. This system, implemented in [`libs/cli/langgraph_cli/analytics.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/analytics.py), collects information such as the operating system, Python version, CLI version, the executed command, and anonymized parameters. Anonymization ensures that sensitive data is not transmitted, replacing variable parameters with a simple [`True`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/_scripts/_patch.py#L76) to indicate their presence. This data is sent to a Supabase backend in a non-blocking background thread, preserving CLI responsiveness. Users have the option to opt out of analytics by setting the [`LANGGRAPH_CLI_NO_ANALYTICS`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/analytics.py#L82) environment variable.

For executing external commands, the CLI provides utilities in [`libs/cli/langgraph_cli/exec.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/exec.py). The [`subp_exec`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/exec.py#L31) function handles asynchronous execution of shell commands, managing input, capturing [`stdout`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/cli.py#L269) and [`stderr`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/exec.py#L55), and offering verbose logging. It includes signal handling for graceful termination of subprocesses, particularly for [`SIGINT`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/exec.py#L63) and [`SIGTERM`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/exec.py#L71). The [`monitor_stream`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/exec.py#L126) function supports reading output from subprocess streams line by line, allowing for custom callbacks and handling potential buffer overruns. The [`Runner`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/exec.py#L12) context manager ensures consistent asynchronous execution across different Python versions.

User feedback for long-running operations is managed through a spinning progress indicator, implemented by the [`Progress`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/progress.py#L7) class in [`libs/cli/langgraph_cli/progress.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/progress.py). This context manager displays a rotating spinner with a customizable message to [`sys.stdout`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/cli.py#L269). It operates as a non-blocking background thread in interactive terminals, allowing the main program flow to continue while providing visual feedback. For non-interactive environments, it gracefully falls back to printing messages to [`sys.stderr`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/exec.py#L100).

## Python SDK for LangGraph

link

zoom\_in

The Python SDK for LangGraph enables programmatic interaction with the LangGraph API, facilitating the management of AI assistants, conversational threads, and graph execution runs. It provides functionalities for persistent storage and is designed with robust authentication, comprehensive data models, and streaming capabilities.

The SDK's core functionality is encapsulated within the [`LangGraphClient`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L248), which offers both asynchronous and synchronous interfaces for communicating with the LangGraph API. This client manages AI assistants, allowing for their creation, retrieval, update, deletion, and search, including versioning and schema management. It also handles conversational threads, providing operations for creation, state management, history retrieval, and streaming of events to maintain graph state across interactions. Furthermore, the client orchestrates graph execution runs, enabling the creation, streaming, and waiting for completion of both stateful and stateless runs. The SDK integrates with a persistent document store, supporting key-value operations for cross-thread memories.

The SDK employs an authentication and authorization framework, defined within the [`libs/sdk-py/langgraph_sdk/auth`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth) directory. This framework allows for custom user authentication and fine-grained access control, where handlers can verify credentials and control access to resources and actions. For instance, developers can register asynchronous functions to authenticate users based on request details and define authorization rules that determine access to specific operations on threads, assistants, or other resources. Errors during authentication or authorization are handled by a custom [`HTTPException`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/exceptions.py#L9) class, which provides structured HTTP error responses.

Data models and schema definitions, found in [`libs/sdk-py/langgraph_sdk/schema.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py), ensure type safety and clarity for API interactions. These models define the structure of requests and responses for entities such as [`Config`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/schemas.py#L414), [`Checkpoint`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py#L172), [`GraphSchema`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py#L185), [`Assistant`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py#L239), [`Thread`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py#L255), [`Run`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py#L315), and [`Cron`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py#L336). They also specify various status definitions, streaming modes, and control flow commands.

For real-time updates and long-running operations, the SDK incorporates Server-Sent Events (SSE) streaming. The [`libs/sdk-py/langgraph_sdk/sse.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/sse.py) module handles the decoding of byte streams into [`StreamPart`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py#L502) objects, which represent individual SSE events. This mechanism allows the client to process events iteratively and efficiently, supporting functionalities like [`Last-Event-ID`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L480) for resuming interrupted streams.

Error handling is managed through a hierarchy of custom exception classes, rooted in [`LangGraphError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L13) and detailed in [`libs/sdk-py/langgraph_sdk/errors.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py). These exceptions cover various HTTP error statuses, connection issues, and response validation failures, allowing for specific error handling based on the nature of the API interaction. Utility functions parse error bodies and map HTTP responses to appropriate exception types, integrating with the underlying [`httpx`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/pyproject.toml#L15) library for both synchronous and asynchronous operations.

### API Client and Resource Management

link

zoom\_in

The [`LangGraphClient`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L248) provides the primary interface for both synchronous and asynchronous interactions with the LangGraph API, facilitating the management of various core resources. This client enables programmatic control over AI assistants, conversational threads, graph execution runs, and scheduled tasks (crons), along with access to a persistent document store. The client orchestrates the underlying HTTP communication, manages efficient JSON serialization using [`orjson`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/pyproject.toml#L16), and supports Server-Sent Events (SSE) streaming for real-time updates. Authentication is handled through API key retrieval, which supports multiple environment variables for flexibility.

The client's design incorporates sub-clients for distinct API resources, promoting a modular structure for API access. These specialized clients handle the creation, updating, deletion, and searching of resources such as assistants, threads, or cron jobs. For instance, [`AssistantsClient`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L571) manages different versions of graph configurations, while [`ThreadsClient`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L1196) handles the state and history of conversational interactions. Graph execution runs are managed by [`RunsClient`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L1844), which supports streaming results and configuring run behavior with parameters like [`stream_mode`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/pregel/main.py#L579) and [`durability`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/tests/conftest.py#L56).

HTTP communication is abstracted by an internal [`HttpClient`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L286) which uses [`httpx`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/pyproject.toml#L15) for requests. This [`HttpClient`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L286) provides methods for standard HTTP verbs (GET, POST, PUT, PATCH, DELETE) and integrates custom JSON serialization and robust error handling. For operations requiring real-time updates, the client leverages SSE streaming, managing event parsing and automatic reconnection logic to ensure continuous data flow even in the presence of transient network disruptions. API key retrieval is prioritized, checking explicit arguments before falling back to environment variables such as [`LANGGRAPH_API_KEY`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L87), [`LANGSMITH_API_KEY`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/langgraph_cli/cli.py#L218), or [`LANGCHAIN_API_KEY`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L89), as implemented in the [`_get_api_key`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L83) function within [`libs/sdk-py/langgraph_sdk/client.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py). Further details on the specific API endpoints and their associated data models can be found in [Data Models and Schema Definition](https://codewiki.google/github.com/langchain-ai/langgraph#python-sdk-for-langgraph-data-models-and-schema-definition).

### Authentication and Authorization Framework

link

zoom\_in

The LangGraph Python SDK includes a flexible framework for managing authentication and authorization, centered around the [`Auth`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/__init__.py#L13) class. This framework allows developers to integrate custom logic for verifying user identities and controlling access to LangGraph resources and actions.

The [`Auth`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/__init__.py#L13) class, defined in [`libs/sdk-py/langgraph_sdk/auth/__init__.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/__init__.py), enables the registration of an asynchronous [`authenticate`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/__init__.py#L189) function. This function processes incoming request details, such as authorization headers, paths, and methods, to verify user credentials and return a user representation. This ensures that every request is authenticated against a custom-defined mechanism.

For authorization, the [`Auth`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/__init__.py#L13) class provides a hierarchical system accessible through its [`on`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/types.py#L931) property. This system uses decorators to define access control rules at different levels of granularity. Developers can register:

- **Global handlers**: Applied to any resource or action by default.
- **Resource-specific handlers**: Applied to all actions on a particular resource, such as [`threads`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/types.py#L961), [`crons`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/types.py#L1034), [`assistants`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/types.py#L998), or the [`store`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/types.py#L1064).
- **Resource and action-specific handlers**: Provide fine-grained control over specific operations, such as creating a thread ( [`on.threads.create`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/concepts/auth.md?plain=1#L393)) or deleting an assistant ( [`on.assistants.delete`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/concepts/auth.md?plain=1#L762)).

This hierarchical structure ensures that the most specific authorization handler takes precedence. An authorization handler receives an [`AuthContext`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/types.py#L383) object, which contains request context and user information, along with the specific data being authorized. Handlers can return [`True`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/_scripts/_patch.py#L76) or [`None`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/_scripts/_patch.py#L17) to accept the request, [`False`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/_scripts/_patch.py#L50) to reject it (triggering a 403 Forbidden error), or a [`FilterType`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/types.py#L58) to apply data filtering to the response.

To provide structured error responses, particularly for authentication and authorization failures, the framework utilizes the [`HTTPException`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/exceptions.py#L9) class, located in [`libs/sdk-py/langgraph_sdk/auth/exceptions.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/exceptions.py). This exception allows handlers to specify an HTTP status code, a detailed error message, and optional HTTP headers, ensuring clear communication of access-related issues to API consumers.

The types used within this authentication and authorization framework, such as [`AuthContext`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/types.py#L383) and various user protocols ( [`MinimalUser`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/types.py#L151), [`BaseUser`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/types.py#L182), [`StudioUser`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/types.py#L218)), are defined in [`libs/sdk-py/langgraph_sdk/auth/types.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/types.py). These type definitions, alongside [`TypedDict`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/agents/agents.md?plain=1#L384) models for API operations, ensure type safety and clarity across the SDK's interactions. The [`AuthContext`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/types.py#L383) dataclass, for instance, passes detailed contextual information, including user permissions and the specific resource and action being requested, to authorization handlers. See [Data Models and Schema Definition](https://codewiki.google/github.com/langchain-ai/langgraph#python-sdk-for-langgraph-data-models-and-schema-definition) for more details on data models.

The [Authentication and Authorization Framework](https://codewiki.google/github.com/langchain-ai/langgraph#python-sdk-for-langgraph-authentication-and-authorization-framework) also uses these types extensively for defining [`AuthContext`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/auth/types.py#L383) and other security-related data structures.

### Server-Sent Events (SSE) Streaming

link

zoom\_in

The Python SDK includes a mechanism for processing Server-Sent Events (SSE) from HTTP responses, enabling real-time updates and long-running operations. This functionality is primarily handled by two components: [`BytesLineDecoder`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/sse.py#L15) and [`SSEDecoder`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/sse.py#L76), which together convert raw byte streams into structured [`StreamPart`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py#L502) objects.

The [`BytesLineDecoder`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/sse.py#L15) is responsible for incrementally reading byte chunks from an HTTP response and splitting them into individual lines. It manages internal buffering for incomplete lines and handles various newline conventions, ensuring that complete lines are identified and extracted from the incoming stream.

Subsequently, the [`SSEDecoder`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/sse.py#L76) takes these decoded lines and parses them according to the SSE specification. It extracts key event fields such as [`event`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/cloud/reference/sdk/js_ts_sdk_ref.md?plain=1#L116), [`data`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/cloud/reference/sdk/js_ts_sdk_ref.md?plain=1#L3158), [`id`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/mkdocs.yml#L201), and [`retry`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/yarn.lock#L27), aggregating them to form a [`StreamPart`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/schema.py#L502) object for each complete event. The [`data`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/cloud/reference/sdk/js_ts_sdk_ref.md?plain=1#L3158) field within an SSE event is deserialized using [`orjson`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/pyproject.toml#L16) for efficient processing. The [`SSEDecoder`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/sse.py#L76) also maintains the [`last_event_id`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/sse.py#L84), which is crucial for resuming streams after disconnections.

The SDK provides both asynchronous and synchronous generators, [`aiter_lines_raw`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/sse.py#L141) and [`iter_lines_raw`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/sse.py#L150) respectively, to iterate over the raw decoded lines from [`httpx.Response`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/sse.py#L141) objects. This allows applications to process event streams in a non-blocking manner or using traditional blocking I/O, depending on the application's design. This system supports client-side stream recovery, automatically re-establishing connections and utilizing the [`Last-Event-ID`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L480) header to continue receiving events seamlessly after transient network disruptions. For further details on the SDK's client implementation, refer to [API Client and Resource Management](https://codewiki.google/github.com/langchain-ai/langgraph#python-sdk-for-langgraph-api-client-and-resource-management).

### Comprehensive Error Handling

link

zoom\_in

The Python SDK incorporates a dedicated framework for managing errors that arise during interactions with the LangGraph API. This framework is built around a custom exception hierarchy, originating from [`LangGraphError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L13) as the base class. This structure enables developers to handle API-related issues with granularity, distinguishing between various types of failures.

At a high level, the error system categorizes exceptions based on their nature:

- **API-related errors**: Represent issues stemming directly from API communication, such as invalid requests or server-side problems. The base for these is [`APIError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L17), which extends [`httpx.HTTPStatusError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/client.py#L420) to integrate seamlessly with the underlying HTTP client. This class includes details from the HTTP response, such as the request and the raw response body, and attempts to extract further structured error information like [`code`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/tutorials/llm-compiler/math_tools.py#L83), [`param`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/cloud/reference/sdk/js_ts_sdk_ref.md?plain=1#L1803), and [`type`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/tests/agents.py#L19) from a JSON response body.
- **Response validation errors**: [`APIResponseValidationError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L53) is a specialized [`APIError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L17) raised when the data returned by the API does not conform to the expected schema, indicating a mismatch between the API contract and the received data.
- **Connection errors**: [`APIConnectionError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L87) addresses problems related to network connectivity, such as an inability to reach the API server. A specific instance, [`APITimeoutError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L94), handles cases where a request exceeds its allotted time limit.
- **HTTP status-specific errors**: A range of exceptions are provided to correspond directly to common HTTP status codes. These include [`BadRequestError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L99) (400), [`AuthenticationError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L103) (401), [`PermissionDeniedError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L107) (403), [`NotFoundError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L111) (404), [`ConflictError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L115) (409), [`UnprocessableEntityError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L119) (422), [`RateLimitError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L123) (429), and [`InternalServerError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L127) (5xx). These exceptions inherit from [`APIStatusError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L73) and explicitly map to their respective status codes.

The SDK integrates these custom exceptions with the [`httpx`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/pyproject.toml#L15) library, which handles HTTP requests. Utility functions are responsible for parsing error responses: [`_extract_error_message`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L131) attempts to find a human-readable message within an error body, while [`_adecode_error_body`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L149) (and its synchronous counterpart [`_decode_error_body`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L165)) decodes response bodies into Python objects. The [`_map_status_error`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L181) function then uses the HTTP status code and the decoded body to select and instantiate the appropriate [`APIStatusError`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L73) subclass. Finally, [`_araise_for_status_typed`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L204) (and [`_raise_for_status_typed`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/sdk-py/langgraph_sdk/errors.py#L215) for synchronous operations) checks the HTTP response status and raises the determined exception if the status code indicates an error (4xx or 5xx). This approach ensures that developers receive meaningful, typed exceptions that facilitate robust error handling logic in their applications.

### SDK Testing and Quality Assurance

link

zoom\_in

The LangGraph Python SDK includes a comprehensive testing suite to ensure the robustness and correctness of its functionalities. This suite covers critical aspects such as API consistency between synchronous and asynchronous clients, the reliability of client-side streaming mechanisms under various network conditions, and the accurate handling of errors.

API parity tests, for instance, confirm that the public methods, parameter signatures, and return types of synchronous client implementations consistently mirror those of their asynchronous counterparts. This ensures a uniform interface regardless of the execution context chosen by developers.

To validate the SDK's streaming capabilities, the tests simulate Server-Sent Events (SSE) parsing, verify the flushing of trailing events, and confirm stream recovery after simulated network disconnects. This is achieved by precisely controlling HTTP responses, including headers, content, and network errors, without relying on actual network requests.

Error handling is another key area of focus, with tests mapping HTTP status codes to specific exception types. These tests ensure that the SDK correctly extracts and propagates details such as status codes, request IDs, and error messages from API responses, providing structured feedback for debugging and error management.

Finally, the testing suite includes checks for schema consistency, validating that the SDK's internal data models align with the OpenAPI specification. This ensures that the selectable fields for various API resources (like Assistants, Threads, and Runs) conform to the API's contract. These tests load the OpenAPI specification and compare its definitions against the SDK's enum members to maintain consistency.

## Example Applications

link

zoom\_in

A collection of practical examples demonstrates various functionalities and use cases of LangGraph. These examples showcase how to implement specific features, such as chatbot simulations and evaluation frameworks, and illustrate different agent workflows and multi-agent systems, serving as a resource for understanding and leveraging LangGraph in real-world scenarios.

One such example is the framework for simulating and evaluating AI assistants. This framework, located in the [`examples/chatbot-simulation-evaluation`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/examples/chatbot-simulation-evaluation) directory, constructs a chat simulation graph using [`StateGraph`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/state.py#L111). It enables the creation of simulated users and orchestrates conversations between an assistant and a simulated user to assess AI assistant performance. Key aspects include managing conversational flow, handling turn limits, and determining when a simulation should continue or terminate based on predefined conditions or specific messages. The framework utilizes LangChain's [`Runnable`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/tests/model.py#L15) interface for composability, allowing flexible integration of different large language models (LLMs) and custom logic for both the assistant and simulated user. State management within the simulation relies on a [`TypedDict`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/agents/agents.md?plain=1#L384) schema, [`SimulationState`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/examples/chatbot-simulation-evaluation/simulation_utils.py#L67), which tracks messages and inputs, and employs [`Annotated`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/how-tos/graph-api.md?plain=1#L238) with [`add_messages`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/examples/graphs/storm.py#L180) to ensure consistent message history updates. Message conversion utilities handle transformations between various message formats, such as [`langchain`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/LICENSE#L3)'s [`BaseMessage`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/agents/context.md?plain=1#L198) and OpenAI-compatible dictionaries, and manage message roles during the simulation. This allows for a robust and type-safe approach to defining conversational state and transitions between different stages of a simulation.

### Chatbot Simulation and Evaluation Framework

link

zoom\_in

The framework for simulating and evaluating AI assistants allows for the construction of a chat simulation graph, the creation of simulated users, and the management of state and conversational flow. This framework utilizes [`langgraph`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/reference/index.md?plain=1#L23)'s [`StateGraph`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/state.py#L111) to define the interaction between an AI assistant and a simulated user, enabling comprehensive assessment of assistant performance.

At its core, the [`create_chat_simulator`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/examples/chatbot-simulation-evaluation/simulation_utils.py#L80) function in [`examples/chatbot-simulation-evaluation/simulation_utils.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/examples/chatbot-simulation-evaluation/simulation_utils.py) builds the simulation graph. This graph orchestrates the turns of conversation, manages message history, and determines when the simulation should conclude, often based on a maximum number of turns or a specific "FINISHED" message.

Simulated users are generated using the [`create_simulated_user`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/examples/chatbot-simulation-evaluation/simulation_utils.py#L32) function, also found in [`examples/chatbot-simulation-evaluation/simulation_utils.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/examples/chatbot-simulation-evaluation/simulation_utils.py). These simulated users are represented as [`Runnable`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/tests/model.py#L15) instances, capable of responding to assistant messages based on a provided language model and a system prompt. This allows for diverse simulated personas and response patterns.

State management within the simulation relies on a [`TypedDict`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/agents/agents.md?plain=1#L384) called [`SimulationState`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/examples/chatbot-simulation-evaluation/simulation_utils.py#L67), defined in [`examples/chatbot-simulation-evaluation/simulation_utils.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/examples/chatbot-simulation-evaluation/simulation_utils.py). This state tracks the ongoing conversation, specifically the list of messages exchanged. The framework uses [`Annotated`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/docs/docs/how-tos/graph-api.md?plain=1#L238) with an [`add_messages`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/cli/examples/graphs/storm.py#L180) function to ensure new messages are consistently appended to the state history, maintaining a coherent conversational context.

The conversational flow within the [`StateGraph`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/langgraph/langgraph/graph/state.py#L111) typically involves nodes for both the "user" and the "assistant." The "user" node processes messages from the assistant, generates a response, and updates the state. Conversely, the "assistant" node receives the current conversation history and produces its next message. Transitions between these nodes are often conditional, using functions like [`_should_continue`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/examples/chatbot-simulation-evaluation/simulation_utils.py#L195) (from [`examples/chatbot-simulation-evaluation/simulation_utils.py`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/examples/chatbot-simulation-evaluation/simulation_utils.py)) to manage the progression or termination of the simulation. For more details on the graph definition and compilation process, refer to [Graph Definition and Compilation](https://codewiki.google/github.com/langchain-ai/langgraph#langgraph-core-framework-graph-definition-and-compilation). The overall architecture leverages the [`Runnable`](https://github.com/langchain-ai/langgraph/blob/df8becd5cfc74bb09ab2d7cbdf17c5559114b8d8/libs/prebuilt/tests/model.py#L15) interface for flexible integration of different large language models and custom logic for both the assistant and simulated user components. Further insights into how LangGraph manages mutable state within graphs can be found in [Channels and State Management](https://codewiki.google/github.com/langchain-ai/langgraph#langgraph-core-framework-channels-and-state-management).
