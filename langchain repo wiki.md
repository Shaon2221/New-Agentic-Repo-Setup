This repository includes libraries and command-line tools for managing, constructing, and interacting with large language model (LLM) applications. This foundation supports AI agent development, integrates with diverse LLM providers, and offers utilities for data processing.

The repository provides several functional areas:

- **LangChain CLI Tooling**
Provides command-line interfaces to create, serve, and manage LangChain applications and integrations. It includes capabilities for code migration and enforcing code quality. See [LangChain CLI Tooling](https://codewiki.google/github.com/langchain-ai/langchain#langchain-cli-tooling) for more details.

- **Core LangChain Abstractions and Utilities ( [`langchain_core`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L274))**
Establishes foundational protocols and interfaces for building AI applications. This includes the [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) protocol for composing components, standardized language model interfaces, a callback system, and unified message types. See [Core LangChain Abstractions and Utilities](https://codewiki.google/github.com/langchain-ai/langchain#core-langchain-abstractions-and-utilities) for more details.

- **LangChain v1 Framework ( [`langchain_v1`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/README.md?plain=1#L11))**
Offers a framework for constructing LLM-powered applications. It supports AI agent orchestration with a modular middleware system, flexible chat model initialization, and embedding model integration. See [LangChain v1 Framework for LLM Applications](https://codewiki.google/github.com/langchain-ai/langchain#langchain-v1-framework-for-llm-applications) for more information.

- **LangChain Compatibility Layer (Classic [`langchain`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L1))**
Provides a transitional layer for older LangChain components. It manages deprecated functionalities and guides migration towards modularized packages. See [LangChain Compatibility Layer (Classic)](https://codewiki.google/github.com/langchain-ai/langchain#langchain-compatibility-layer-classic) for more details.

- **LLM Model Profiles**
Centralizes a system for accessing and managing LLM capabilities, features, and constraints. This ensures consistent retrieval of model-specific information. See [LLM Model Profiles](https://codewiki.google/github.com/langchain-ai/langchain#llm-model-profiles) for more details.

- **Integrations with Third-Party Providers**
Offers direct interfaces to external AI service providers and databases. This includes support for specific LLM providers and vector stores. See [Integrations with Third-Party Providers](https://codewiki.google/github.com/langchain-ai/langchain#integrations-with-third-party-providers) for more details.

- **Text Splitting Strategies**
Provides methods for segmenting text into manageable chunks. These strategies support various document types and programming languages while preserving contextual meaning. See [Text Splitting Strategies](https://codewiki.google/github.com/langchain-ai/langchain#text-splitting-strategies) for more details.


## LangChain CLI Tooling

link

zoom\_in

The LangChain Command-Line Interface (CLI) provides tools for managing LangChain applications and templates. It enables scaffolding new projects, serving applications locally, managing dependencies, and migrating code. The CLI also includes support for developing new integrations and contains internal tooling for maintaining code quality through linting, formatting, and testing.

The primary entry point for the CLI is defined in [`libs/cli/langchain_cli/cli.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py), which integrates various subcommands for different aspects of LangChain development. For instance, the [`app`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py#L16) subcommand in [`libs/cli/langchain_cli/namespaces/app.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/app.py) facilitates application management, including creating new applications from a [`project_template`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/app.py#L99), adding or removing dependencies, and serving applications. The [`template`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/prompts/image.py#L19) subcommand, detailed in [`libs/cli/langchain_cli/namespaces/template.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/template.py), assists in managing installable LangChain templates by providing functionalities to create new templates from boilerplate and serve them locally for development.

For integration development, the [`integration`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L74) subcommand in [`libs/cli/langchain_cli/namespaces/integration.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/integration.py) allows scaffolding new integration packages based on a structured [`integration_template`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/Makefile#L44). This template includes pre-defined components for various AI model types and services, ensuring consistency across integrations. The CLI also offers capabilities for code migration. The [`migrate`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/main.py#L17) subcommand in [`libs/cli/langchain_cli/namespaces/migrate/main.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/main.py) leverages [`gritql`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/pyproject.toml#L15) to refactor Python import statements and facilitate transitions to new package structures, supporting both generic and partner-specific migrations. Further details on this capability can be found in [Code Migration Tooling](https://codewiki.google/github.com/langchain-ai/langchain#langchain-cli-tooling-code-migration-tooling).

The CLI utilizes a set of core utilities for tasks such as Git repository management (parsing dependency strings, cloning, updating), interacting with the GitHub API for package discovery, modifying [`pyproject.toml`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py#L77) files, and tracking analytics events. These utilities are centralized in the [`libs/cli/langchain_cli/utils`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/utils) directory. The overall development and testing workflow for the CLI is managed via a [`Makefile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/.editorconfig#L43) located at [`libs/cli/Makefile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/Makefile), which orchestrates linting, formatting, and a comprehensive suite of unit and integration tests. For more information on these foundational components, refer to [Core Utilities and Testing Infrastructure](https://codewiki.google/github.com/langchain-ai/langchain#langchain-cli-tooling-core-utilities-and-testing-infrastructure).

### Application and Template Scaffolding

link

zoom\_in

LangChain provides Command Line Interface (CLI) tooling to streamline the creation and management of LangChain applications and templates. This tooling uses predefined project and package templates to scaffold new applications, with options for seeding initial packages.

The process of creating a new LangChain application typically involves generating a project structure based on a template found in [`libs/cli/langchain_cli/project_template`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/project_template). This project template includes Dockerization capabilities, setup instructions, and an entry point for serving LangChain APIs. When a new application is created using the [`new`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/app.py#L36) command of the CLI (defined in [`libs/cli/langchain_cli/namespaces/app.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/app.py)), the template is copied to the specified destination. During this process, placeholders within files like [`README.md`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/README.md?plain=1#L17) and [`pyproject.toml`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py#L77) are replaced with the actual application name, ensuring the new project is properly initialized. An application can also be seeded with initial packages during its creation.

Similarly, new LangChain template packages can be generated using a template from [`libs/cli/langchain_cli/package_template`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/package_template). The [`new`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/app.py#L36) command within the template management CLI (defined in [`libs/cli/langchain_cli/namespaces/template.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/template.py)) copies this boilerplate, renames directories and files, and replaces placeholders in configuration files such as [`pyproject.toml`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py#L77) and [`__init__.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/_import_utils.py#L11), as well as the [`README.md`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/README.md?plain=1#L17). An example of such a package template, located in [`libs/cli/langchain_cli/package_template/package_template`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/package_template/package_template), demonstrates defining an AI chain, in this case, a pirate-speaking assistant. This chain is composed of a [`ChatPromptTemplate`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/prompts/chat.py#L774) and [`ChatOpenAI`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/openai/langchain_openai/chat_models/base.py#L2159) and is designed to be directly importable and servable via LangServe.

The CLI also facilitates the management of these packages within an application. The [`add`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/app.py#L128) command, defined in [`libs/cli/langchain_cli/namespaces/app.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/app.py), allows developers to incorporate new templates from various sources, including Git repositories. This command copies the template into the application's [`packages`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/README.md?plain=1#L1) directory, updates the main [`pyproject.toml`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py#L77) with the new dependencies, and provides instructions on how to integrate the template's routes into the application's [`server.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/package_template/README.md?plain=1#L29) file. Conversely, the [`remove`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/app.py#L304) command can delete a package and clean up its entries from [`pyproject.toml`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py#L77).

For serving applications, the project template includes an [`app`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py#L16) directory (specifically [`libs/cli/langchain_cli/project_template/app`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/project_template/app)). The [`server.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/package_template/README.md?plain=1#L29) file within this directory initializes a FastAPI application, which redirects requests to the root path to API documentation and includes a placeholder for integrating LangChain runnables. This setup allows developers to expose their LangChain components as API endpoints. The CLI's [`serve`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py#L63) command (from [`libs/cli/langchain_cli/namespaces/app.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/app.py)) can then be used to run this FastAPI application locally using Uvicorn.

### Integration Template Development

link

zoom\_in

The LangChain CLI provides a comprehensive template for developing new LangChain integrations, streamlining the process of connecting LangChain applications to various AI models and services. This template includes pre-structured components and a robust development workflow, ensuring consistency and adherence to LangChain standards.

The core of this capability resides in the integration template directory, [`libs/cli/langchain_cli/integration_template`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/integration_template), which serves as a blueprint for new integrations. When creating a new integration, the CLI uses the [`new`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/app.py#L36) command within [`libs/cli/langchain_cli/namespaces/integration.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/integration.py) to scaffold a complete package from this template. This process involves copying template files, performing string replacements for module and package names, and optionally installing dependencies.

The template offers pre-defined structures for a variety of AI component types:

- **Chat Models**: A template for implementing [`langchain_core.language_models.BaseChatModel`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/chat_models/base.py#L194) is provided in [`libs/cli/langchain_cli/integration_template/integration_template/chat_models.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/integration_template/integration_template/chat_models.py), supporting synchronous generation and streaming, and handling different message types.
- **Document Loaders**: The template in [`libs/cli/langchain_cli/integration_template/integration_template/document_loaders.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/integration_template/integration_template/document_loaders.py) offers a structure for custom document loaders that inherit from [`BaseLoader`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/document_loaders/base.py#L26), focusing on lazy loading mechanisms.
- **Embeddings**: For integrating embedding models, [`__ModuleName__Embeddings`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/integration_template/integration_template/embeddings.py#L6) in [`libs/cli/langchain_cli/integration_template/integration_template/embeddings.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/integration_template/integration_template/embeddings.py) provides a structure for implementing the [`Embeddings`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/embeddings/embeddings.py#L8) interface.
- **Retrievers**: A blueprint for [`langchain_core.retrievers.BaseRetriever`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/.grit/patterns/langchain_to_core.json#L1004) implementations is available in [`libs/cli/langchain_cli/integration_template/integration_template/retrievers.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/integration_template/integration_template/retrievers.py), guiding the creation of custom document retrieval mechanisms.
- **Toolkits**: Toolkits, which encapsulate collections of tools, are structured via [`__ModuleName__Toolkit`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/integration_template/integration_template/toolkits.py#L8) in [`libs/cli/langchain_cli/integration_template/integration_template/toolkits.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/integration_template/integration_template/toolkits.py), extending [`BaseToolkit`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L1477).
- **Tools**: Individual tools that language models can invoke are defined using [`__ModuleName__Tool`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/integration_template/integration_template/tools.py#L25) in [`libs/cli/langchain_cli/integration_template/integration_template/tools.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/integration_template/integration_template/tools.py), including input schema definitions via Pydantic.
- **Vector Stores**: For managing document embeddings, the template in [`libs/cli/langchain_cli/integration_template/integration_template/vectorstores.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/integration_template/integration_template/vectorstores.py) implements an in-memory [`VectorStore`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/vectorstores/base.py#L43) based on [`langchain_core.vectorstores.VectorStore`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/.grit/patterns/community_to_core.json#L99), supporting storage, retrieval, and similarity search.

The [`Makefile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/.editorconfig#L43) located at [`libs/cli/langchain_cli/integration_template/Makefile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/integration_template/Makefile) manages the development workflow for these integrations. It includes targets for testing, linting, and formatting, ensuring code quality and consistency. Additionally, the [`create_doc`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/integration.py#L208) command in [`libs/cli/langchain_cli/namespaces/integration.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/integration.py) reuses the template's file copying and replacement logic to generate integration documentation based on predefined templates.

For details on ensuring code quality within these integrations, refer to [Quality Assurance for Integrations](https://codewiki.google/github.com/langchain-ai/langchain#langchain-cli-tooling-integration-template-development-quality-assurance-for-integrations).

#### Quality Assurance for Integrations

link

zoom\_in

Within the LangChain CLI's integration template, quality assurance is maintained through a combination of scripts and a standardized testing framework. A core aspect of this assurance involves verifying the structural integrity and dependency hygiene of integration code.

The [`scripts`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/.editorconfig#L38) directory within the integration template provides tools to enforce these architectural constraints. For instance, a Python script ( [`libs/cli/langchain_cli/integration_template/scripts/check_imports.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/integration_template/scripts/check_imports.py)) is used to confirm the importability of Python files. This script attempts to load each specified file as a module, catching any exceptions that arise during the import process. This mechanism helps ensure that Python files within an integration are syntactically correct and that their declared dependencies are resolvable, preventing fundamental loading issues.

In addition to importability, a shell script ( [`libs/cli/langchain_cli/integration_template/scripts/lint_imports.sh`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/integration_template/scripts/lint_imports.sh)) enforces a critical dependency rule: direct imports from core LangChain libraries (e.g., [`langchain`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L1), [`langchain_experimental`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/scripts/lint_imports.sh#L8), [`langchain_community`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/SECURITY.md?plain=1#L61)) are prohibited within integration templates. This rule promotes a clean and consistent dependency structure, encouraging integrations to define their own abstractions rather than tightly coupling to the internal implementations of the main LangChain packages. Violations of this rule are flagged as errors, ensuring that integrations remain modular and avoid potential issues arising from changes in the core libraries.

Beyond these structural checks, the integration template also includes comprehensive unit and integration test suites. These tests leverage base test classes to provide standardized validation for various LangChain components like chat models, embedding models, retrievers, tools, and vector stores. This includes placeholder tests that confirm the compilability of integration tests without actual execution, which is useful for build validation. For a broader understanding of the CLI's testing infrastructure, refer to [Core Utilities and Testing Infrastructure](https://codewiki.google/github.com/langchain-ai/langchain#langchain-cli-tooling-core-utilities-and-testing-infrastructure).

### Code Migration Tooling

link

zoom\_in

The LangChain Command Line Interface (CLI) includes code migration capabilities designed to assist users in refactoring Python import statements. This functionality primarily facilitates transitions to newer package structures, leveraging [`gritql`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/pyproject.toml#L15) for automated code transformations. The migration process supports both generic refactoring across packages and partner-specific changes.

The CLI's migration tool, accessible via the [`migrate`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/main.py#L17) command in [`libs/cli/langchain_cli/namespaces/migrate/main.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/main.py), guides users through the refactoring process. It provides warnings and instructions, including advice to run migrations in stages (e.g., from [`langchain`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L1) to [`community`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/README.md?plain=1#L40) packages, then to partner-specific packages). Users can preview changes without applying them using a [`--diff`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/Makefile#L13) or [`--dry-run`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/main.py#L66) flag, or confirm changes interactively with an [`--interactive`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/main.py#L64) flag. The core of these transformations is handled by [`gritql`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/pyproject.toml#L15), which applies predefined patterns.

The [`gritql`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/pyproject.toml#L15) patterns, stored in the [`.grit`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/scripts/generate_migrations.py#L65) directory within the migration namespace (e.g., [`libs/cli/langchain_cli/namespaces/migrate/.grit`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/.grit)), define the specific rules for refactoring. These patterns are designed to move imports from monolithic [`langchain`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L1) and [`langchain_community`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/SECURITY.md?plain=1#L61) modules to more specialized, partner-oriented packages like [`langchain_openai`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/openai/Makefile#L46) or [`langchain_anthropic`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/anthropic/Makefile#L35). The patterns accommodate various import scenarios, including single imports, transitioning [`langchain_community`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/SECURITY.md?plain=1#L61) imports to partner packages, and ensuring that unrelated imports remain unaffected.

A dedicated generation utility within [`libs/cli/langchain_cli/namespaces/migrate/generate`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/generate) is responsible for dynamically creating these migration paths and [`grit`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py#L32) patterns. This utility identifies how classes and functions have moved between packages (e.g., from [`langchain`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L1) to [`langchain-community`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/SECURITY.md?plain=1#L47) or [`langchain-core`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L270)). It then constructs simplified import paths, mapping old module locations to new ones. For partner packages, it identifies classes implementing core LangChain components and generates corresponding migration mappings from [`langchain_community`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/SECURITY.md?plain=1#L61) to the partner package. These generated mappings are then formatted into [`grit`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py#L32) patterns, ready for execution by the CLI. Further details on the structure and generation of these patterns are available in [Grit Patterns and Generation](https://codewiki.google/github.com/langchain-ai/langchain#langchain-cli-tooling-code-migration-tooling-grit-patterns-and-generation).

#### Grit Patterns and Generation

link

zoom\_in

The [`grit`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py#L32) patterns are integral to the CLI's code migration capabilities, enabling automated refactoring of Python import statements. These patterns are structured to facilitate transitions, particularly for remapping modules within the LangChain ecosystem.

The generation of these patterns is a dynamic process. For generic migrations, functions such as [`generate_simplified_migrations`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/generate/generic.py#L143) in [`libs/cli/langchain_cli/namespaces/migrate/generate/generic.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/generate/generic.py) analyze existing package structures to identify modules and classes that have moved between packages (e.g., from a monolithic [`langchain`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L1) package to [`langchain-community`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/SECURITY.md?plain=1#L47) or [`langchain-core`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L270)). This process involves scanning source and target packages to map old import paths to new ones, optionally simplifying these paths when top-level re-exports are available. Similarly, for partner-specific migrations, [`get_migrations_for_partner_package`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/generate/partner.py#L21) in [`libs/cli/langchain_cli/namespaces/migrate/generate/partner.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/generate/partner.py) identifies classes within partner packages that inherit from core LangChain components and generates corresponding import migrations from the [`COMMUNITY_PKG`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/generate/utils.py#L17) to the specific partner package. The identified migration pairs are then transformed into [`grit`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py#L32) language patterns by [`dump_migrations_as_grit`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/generate/grit.py#L17) in [`libs/cli/langchain_cli/namespaces/migrate/generate/grit.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/generate/grit.py), which formats them into a structure consumable by the [`grit`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py#L32) tool for automated code modifications.

The correctness of these [`grit`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py#L32) patterns is validated through a comprehensive testing methodology. Test cases define various migration scenarios, including single imports, transitions from community to partner packages, and cases where imports should remain unaffected. These tests specify both the "before" and "after" states of Python code snippets, ensuring that the [`langchain_all_migrations()`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/.grit/patterns/everything.grit#L3) [`grit`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/cli.py#L32) pattern performs the expected transformations. The test suite for the CLI's [`migrate`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/namespaces/migrate/main.py#L17) command, described in [Code Migration Tooling](https://codewiki.google/github.com/langchain-ai/langchain#langchain-cli-tooling-code-migration-tooling), further validates the end-to-end migration process, comparing the file system structure and content after a migration operation against expected outcomes.

The [`langchain_core`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L274) library provides the foundational abstractions and protocols that underpin the entire LangChain ecosystem. It aims to establish modularity, stability, and broad compatibility for AI applications by defining core interfaces and a universal invocation protocol.

Central to this foundation is the [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) interface, which defines a standard for any component in LangChain to be executed synchronously, asynchronously, in batches, and streamed. This interface facilitates the creation of complex workflows through the LangChain Expression Language (LCEL), enabling declarative composition of [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) units. The structure and execution of these [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) objects can be configured through a robust system that supports advanced settings, retry mechanisms, and conditional logic. For a detailed exploration of the [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) protocol and LCEL, refer to [The Runnable Protocol and LCEL](https://codewiki.google/github.com/langchain-ai/langchain#core-langchain-abstractions-and-utilities-the-runnable-protocol-and-lcel).

Beyond the [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) protocol, [`langchain_core`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L274) defines the core interfaces for key AI components, including abstract base classes for language models (LLMs) and chat models, standardizing interactions and enabling integrations with various providers. These abstractions manage essential functionalities such as caching, callbacks, and the handling of multimodal messages. For more information on these interfaces, see [Language Model Abstractions](https://codewiki.google/github.com/langchain-ai/langchain#core-langchain-abstractions-and-utilities-language-model-abstractions).

The library also includes a robust, event-driven callback system that allows developers to inject custom logic, logging, streaming, and tracing into various operations involving LLMs, chains, agents, tools, and retrievers. This system supports both synchronous and asynchronous contexts, offering fine-grained control over application behavior. More details on this system can be found in [Callback System](https://codewiki.google/github.com/langchain-ai/langchain#core-langchain-abstractions-and-utilities-callback-system).

For persistent state and data management, [`langchain_core`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L274) offers mechanisms for serialization and deserialization, allowing LangChain objects to be converted to and from JSON formats. This capability is essential for saving, loading, and sharing application components while maintaining security and version compatibility. Data handling in retrieval-augmented generation (RAG) pipelines is also addressed through abstractions for documents and an indexing mechanism for managing vector stores. Further information on these aspects is available in [Serialization and Deserialization](https://codewiki.google/github.com/langchain-ai/langchain#core-langchain-abstractions-and-utilities-serialization-and-deserialization) and [Data Handling and Indexing for RAG](https://codewiki.google/github.com/langchain-ai/langchain#core-langchain-abstractions-and-utilities-data-handling-and-indexing-for-rag).

To ensure consistency and type safety across AI interactions, [`langchain_core`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L274) defines standardized message types, providing a unified way to represent [`AIMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/ai.py#L153), [`HumanMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/human.py#L9), [`SystemMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/system.py#L9), and [`ToolMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/tool.py#L26). These messages support various content representations, including multimodal blocks, and provide utilities for manipulation and streaming. Refer to [Standardized Message Types](https://codewiki.google/github.com/langchain-ai/langchain#core-langchain-abstractions-and-utilities-standardized-message-types) for more details.

Finally, [`langchain_core`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L274) includes components for defining, managing, converting, and rendering AI agent tools, leveraging schema validation to ensure robust and predictable tool execution. This allows seamless integration of custom tools into [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) chains and agent systems. See [Tool Definitions and Management](https://codewiki.google/github.com/langchain-ai/langchain#core-langchain-abstractions-and-utilities-tool-definitions-and-management) for additional information.

The [`langchain_core`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L274) library also incorporates development tooling and testing infrastructure to maintain code quality and performance. This includes scripts for import validation and linting, along with comprehensive unit and integration tests. [Development Tooling and Testing](https://codewiki.google/github.com/langchain-ai/langchain#core-langchain-abstractions-and-utilities-development-tooling-and-testing) provides more context on this. The core of the LangChain framework revolves around the universal [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) protocol, which defines a standard interface for any component capable of executing a unit of work. This protocol, central to the LangChain Expression Language (LCEL), enables synchronous, asynchronous, batch, and streaming execution modes, providing a flexible foundation for building complex language model applications. The [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) interface supports various operations, including [`invoke`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L591) for single inputs, [`batch`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L863) for lists of inputs, and [`stream`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L1126)/ [`astream`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L1147) for continuous output. These runnables can be composed together using operators like [`|`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/Makefile#L13) (pipe) to form [`RunnableSequence`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L2789) s, allowing for declarative construction of processing chains.

Beyond basic execution, the [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) protocol incorporates mechanisms for robust application design. Configuration management is handled through [`RunnableConfig`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/config.py#L49) (defined in /langchain-ai/langchain/libs/core/langchain\_core/runnables/config.py), which centralizes settings for callbacks, tracing, and concurrency. Error handling and fault tolerance are addressed through features like [`with_retry`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L1850) and [`with_fallbacks`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L1937) (implemented by [`RunnableRetry`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/retry.py#L48) in /langchain-ai/langchain/libs/core/langchain\_core/runnables/retry.py and [`RunnableWithFallbacks`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/fallbacks.py#L37) in /langchain-ai/langchain/libs/core/langchain\_core/runnables/fallbacks.py, respectively). These allow developers to define automatic retries for transient failures and specify alternative execution paths when errors occur.

LCEL also provides specialized runnables for controlling data flow and behavior. [`RunnableBranch`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/branch.py#L42) (defined in /langchain-ai/langchain/libs/core/langchain\_core/runnables/branch.py) enables conditional execution, allowing different branches of a workflow to be selected based on specific criteria. [`RunnablePassthrough`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/passthrough.py#L74), [`RunnableAssign`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/passthrough.py#L352), and [`RunnablePick`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/passthrough.py#L671) (from /langchain-ai/langchain/libs/core/langchain\_core/runnables/passthrough.py) offer utilities for manipulating dictionary inputs, such as passing inputs directly, assigning new key-value pairs, or extracting specific keys. For dynamic behavior, [`DynamicRunnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/configurable.py#L49), [`RunnableConfigurableFields`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/configurable.py#L318), and [`RunnableConfigurableAlternatives`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/configurable.py#L475) (from /langchain-ai/langchain/libs/core/langchain\_core/runnables/configurable.py) allow for runtime configuration of runnable components or the swapping of entire implementations based on specified parameters.

Additionally, [`RouterRunnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/router.py#L46) (defined in /langchain-ai/langchain/libs/core/langchain\_core/runnables/router.py) facilitates dynamic routing of inputs to different [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) instances based on a key, enabling flexible and adaptive execution paths within an application. For conversational applications, [`RunnableWithMessageHistory`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/history.py#L38) (from /langchain-ai/langchain/libs/core/langchain\_core/runnables/history.py) provides automated management of chat message history, abstracting the complexities of persisting and retrieving conversation states. The structure of these runnables can be represented and visualized as directed acyclic graphs (DAGs) using tools described in [Visualization of Runnables](https://codewiki.google/github.com/langchain-ai/langchain#core-langchain-abstractions-and-utilities-the-runnable-protocol-and-lcel-visualization-of-runnables).

### Callback System

link

zoom\_in

LangChain's event-driven callback system enables custom logic execution, logging, streaming, and tracing throughout the lifecycle of operations involving LLMs, Chains, Agents, Tools, and Retrievers, supporting both synchronous and asynchronous contexts. This system is centered around [`BaseCallbackHandler`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/base.py#L425) and [`BaseCallbackManager`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/base.py#L885) to provide hooks into various stages of an application's execution.

The core interface for defining custom actions is the [`BaseCallbackHandler`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/base.py#L425) located in [`libs/core/langchain_core/callbacks/base.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/base.py). Developers extend this abstract class to override methods for specific events, such as [`on_llm_start`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tracers/base.py#L93), [`on_chain_end`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tracers/base.py#L284), [`on_agent_action`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/base.py#L157), [`on_tool_end`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tracers/base.py#L386), and [`on_retriever_error`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tracers/base.py#L473). There is also an [`AsyncCallbackHandler`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/base.py#L477) for asynchronous environments. These handlers can selectively ignore certain event types to optimize dispatch.

The [`BaseCallbackManager`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/base.py#L885) in [`libs/core/langchain_core/callbacks/manager.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/manager.py) is responsible for orchestrating these handlers. It manages a collection of [`BaseCallbackHandler`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/base.py#L425) instances, along with associated tags and metadata, which are propagated through an execution hierarchy using [`run_id`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L796) and [`parent_run_id`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tracers/base.py#L47). This manager dispatches events to registered handlers and integrates with tracing systems like LangSmith, enabling detailed observation and debugging of complex AI workflows. It supports both synchronous and asynchronous event dispatch, including mechanisms to manage concurrency and protect asynchronous callbacks from cancellation.

Specialized callback handlers exist for common use cases:

- [`FileCallbackHandler`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/file.py#L21) (in [`libs/core/langchain_core/callbacks/file.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/file.py)) logs events to a specified file, with a strong recommendation for use as a context manager to ensure proper resource handling.
- [`StdOutCallbackHandler`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/stdout.py#L16) (in [`libs/core/langchain_core/callbacks/stdout.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/stdout.py)) prints events to standard output, providing immediate visual feedback during development.
- [`StreamingStdOutCallbackHandler`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/streaming_stdout.py#L18) (in [`libs/core/langchain_core/callbacks/streaming_stdout.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/streaming_stdout.py)) is specifically designed to stream individual LLM tokens to [`sys.stdout`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/streaming_stdout.py#L54) in real-time, enhancing user experience for interactive applications.
- [`UsageMetadataCallbackHandler`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/usage.py#L18) (in [`libs/core/langchain_core/callbacks/usage.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/usage.py)) collects and aggregates token usage metadata from LLM responses, organized by model name, which is useful for cost tracking and performance analysis. This handler can be managed via a context manager for implicit availability across LLM calls.

The [`langchain_core.callbacks`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L302) package dynamically imports these components, offering a flat and user-friendly API for accessing the various callback handlers and managers, as shown in [`libs/core/langchain_core/callbacks/__init__.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/callbacks/__init__.py). This design choice improves ease of use and optimizes startup performance by loading components only when they are accessed.

### Language Model Abstractions

zoom\_in

The LangChain framework provides a set of core abstractions for interacting with various language models (LLMs) and chat models, standardizing how applications leverage AI. These abstractions manage common functionalities such as prompt generation, token counting, caching, and callback mechanisms, ensuring consistent interaction regardless of the underlying model provider. The module [`libs/core/langchain_core/language_models/__init__.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/__init__.py) acts as a central access point, dynamically importing different language model classes and functions to optimize load times and maintain a clean API.

At the base level, the [`BaseLanguageModel`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/base.py#L115) in [`libs/core/langchain_core/language_models/base.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/base.py) defines the fundamental interface for all language model integrations. This abstract class specifies methods for synchronous and asynchronous text generation ( [`generate_prompt`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/llms.py#L776), [`agenerate_prompt`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/llms.py#L787)), token counting, and includes configuration options for caching, verbosity, and callbacks. By inheriting from [`RunnableSerializable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L2568), these models seamlessly integrate with the LangChain Expression Language (LCEL). See [The Runnable Protocol and LCEL](https://codewiki.google/github.com/langchain-ai/langchain#core-langchain-abstractions-and-utilities-the-runnable-protocol-and-lcel) for more information on [`RunnableSerializable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L2568). The framework also includes a default GPT-2 tokenizer for general token counting, which can be overridden by model-specific tokenizers for improved accuracy.

For message-based interactions, the [`BaseChatModel`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/chat_models.py#L248) class, defined in [`libs/core/langchain_core/language_models/chat_models.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/chat_models.py), extends [`BaseLanguageModel`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/base.py#L115) to provide a standardized interface for chat-oriented LLMs. This abstraction supports various interaction patterns, including direct invocation ( [`invoke`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L591), [`ainvoke`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L601)), streaming responses ( [`stream`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L1126), [`astream`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L1147)), and batch processing ( [`generate`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/chains/llm.py#L120), [`agenerate`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/chains/llm.py#L147)). [`BaseChatModel`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/chat_models.py#L248) integrates a robust callback system for monitoring and logging interactions, and a caching mechanism to reduce redundant API calls. A notable feature is its support for structured output and tool binding, allowing models to generate responses conforming to specified schemas or to invoke external tools. The framework can automatically handle multimodal messages by standardizing content blocks to a unified LangChain v1 format, as detailed in [`libs/core/langchain_core/language_models/_utils.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/_utils.py).

Traditional string-in, string-out models are managed by [`BaseLLM`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/llms.py#L290) and [`LLM`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/llms.py#L1396) in [`libs/core/langchain_core/language_models/llms.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/llms.py). These classes extend [`BaseLanguageModel`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/base.py#L115) to provide standard methods for text generation, streaming, and caching. They also incorporate error handling with retry mechanisms and integrate with LangSmith for tracing, aiding in observability and debugging. While [`BaseLLM`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/llms.py#L290) provides a comprehensive interface, [`LLM`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/llms.py#L1396) offers a simpler entry point for basic implementations.

To facilitate testing and development, the framework includes fake implementations of both LLMs and chat models. [`FakeListLLM`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/fake.py#L19) and [`FakeStreamingListLLM`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/fake.py#L85) in [`libs/core/langchain_core/language_models/fake.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/fake.py) simulate traditional LLM responses and streaming behavior. ### Standardized Message Types

link

zoom\_in

The LangChain framework provides a standardized and extensible system for representing and managing messages exchanged with Large Language Models (LLMs). This system abstracts away provider-specific message formats, ensuring consistent development and interoperability across various AI models. At its core, the message handling system defines fundamental abstractions for AI interaction, content representation, and mechanisms for manipulating these messages.

All messages are built upon a common foundation defined by [`BaseMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/base.py#L93) and [`BaseMessageChunk`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/base.py#L375) in \[/langchain-ai/langchain/libs/core/langchain\_core/messages/base.py\]. [`BaseMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/base.py#L93) serves as an abstract base for chat model inputs and outputs, encompassing fields for content, additional keyword arguments, response metadata, message type, name, and ID. [`BaseMessageChunk`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/base.py#L375) extends this to handle streamable message parts, enabling the incremental construction of messages during streaming. The system includes a [`TextAccessor`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/base.py#L47) to provide backward compatibility for accessing message content, transitioning from method-based [`.text()`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/base.py#L52) to property-based [`.text`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/base.py#L53).

Specific message types cater to different roles in an AI conversation:

- [`AIMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/ai.py#L153) in \[/langchain-ai/langchain/libs/core/langchain\_core/messages/ai.py\] represents responses from an AI, including potential tool calls, invalid tool calls, and token usage metadata. Its chunked counterpart, [`AIMessageChunk`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/ai.py#L380), supports streaming AI responses and aggregation of tool call chunks.
- [`HumanMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/human.py#L9) in \[/langchain-ai/langchain/libs/core/langchain\_core/messages/human.py\] encapsulates user input, while [`HumanMessageChunk`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/human.py#L63) handles partial or streamed user messages.
- [`SystemMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/system.py#L9) in \[/langchain-ai/langchain/libs/core/langchain\_core/messages/system.py\] is used for providing initial instructions or context to the AI, with [`SystemMessageChunk`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/system.py#L63) for streaming.
- [`ChatMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/chat.py#L15) in \[/langchain-ai/langchain/libs/core/langchain\_core/messages/chat.py\] offers a general-purpose message type with an arbitrary [`role`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/prompty/README.md?plain=1#L61) attribute, allowing flexible assignment of speakers in a conversation. [`ChatMessageChunk`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/chat.py#L25) provides streaming support for these messages.
- [`ToolMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/tool.py#L26) in \[/langchain-ai/langchain/libs/core/langchain\_core/messages/tool.py\] represents the results of tool executions, linked to specific tool calls via [`tool_call_id`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L613). [`ToolMessageChunk`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/tool.py#L173) facilitates streaming tool output. This also includes [`ToolCall`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/tool.py#L205) and [`ToolCallChunk`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/tool.py#L251) for model-requested tool invocations and their partial streaming counterparts. An older [`FunctionMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/function.py#L15) in \[/langchain-ai/langchain/libs/core/langchain\_core/messages/function.py\] schema is also present, primarily for backward compatibility.
- [`RemoveMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/modifier.py#L8) in \[/langchain-ai/langchain/libs/core/langchain\_core/messages/modifier.py\] is a specialized message type used to signal the removal of another message by its [`id`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/base.py#L135).

Multimodal content is handled through standardized [`TypedDict`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/utils/git.py#L10) content blocks defined in \[/langchain-ai/langchain/libs/core/langchain\_core/messages/content.py\]. These blocks provide a unified, provider-agnostic format for various data types, such as text, images, video, audio, files, tool calls, reasoning, and citations. Factory functions simplify the creation of these content blocks, ensuring consistency and automatic ID generation. The [`extras`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/ai.py#L277) field allows for provider-specific metadata within standard blocks, providing extensibility.

The system also includes robust mechanisms for message manipulation and transformation, as detailed in \[/langchain-ai/langchain/libs/core/langchain\_core/messages/utils.py\]. These utilities support:

- **Serialization and Deserialization**: Converting message objects to and from dictionary representations.
- **Filtering**: Selecting messages based on criteria like name, type, ID, or tool calls.
- **Merging**: Combining consecutive messages of the same type, consolidating content and metadata.
- **Trimming**: Reducing the total token count of a sequence of messages, supporting strategies to prioritize either the beginning or end of the message history.
- **OpenAI Format Conversion**: Translating LangChain's internal message representations into OpenAI API compatible formats.
- **Approximate Token Counting**: Estimating token counts for messages using character-based approximation.

A critical aspect of this standardization is the [`block_translators`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/ai.py#L246) directory in \[/langchain-ai/langchain/libs/core/langchain\_core/messages/block\_translators\]. This component is responsible for converting diverse AI message content from various model providers (e.g., OpenAI, Anthropic, Bedrock, Google GenAI, Groq) into the standardized [`ContentBlock`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/content.py#L825) format. It uses a registry to map [`model_provider`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/ai.py#L244) names to specific translation functions, ensuring broad compatibility and enabling seamless integration of different LLM providers into the LangChain ecosystem. This architecture ensures consistent handling of AI model outputs, abstracting away provider-specific content representations and facilitating robust integration and data processing.

### Tool Definitions and Management

link

zoom\_in

LangChain's core library provides components for defining and managing AI agent tools. At its foundation, the [`BaseTool`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L390) abstract class, found in [`libs/core/langchain_core/tools/base.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py), integrates with Pydantic for schema definition and the [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) protocol for execution. This base class handles input parsing, schema generation, and both synchronous ( [`_run`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L692)) and asynchronous ( [`_arun`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L702)) execution, alongside callback management and error handling. Tools can define their input arguments using a Pydantic [`BaseModel`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/pyproject.toml#L84) or a JSON schema, which is used for validation and description for language models.

The [`tool`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/simple.py#L30) decorator and [`convert_runnable_to_tool`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/convert.py#L397) function, defined in [`libs/core/langchain_core/tools/convert.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/convert.py), facilitate the creation of [`BaseTool`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L390) instances from Python functions or [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) objects. These utilities support automatic schema inference from function type hints or [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) input schemas, allowing for flexible tool definitions. The description of a tool can be explicitly provided or inferred from docstrings, including Google-style docstrings for richer parameter descriptions.

For straightforward use cases, the [`Tool`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/simple.py#L30) class in [`libs/core/langchain_core/tools/simple.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/simple.py) extends [`BaseTool`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L390) to wrap Python callables or coroutines. It simplifies tool creation by automatically handling argument parsing for single-input tools and supports both synchronous and asynchronous execution with [`ainvoke`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L601) providing a fallback for synchronous functions.

When structured inputs are required, the [`StructuredTool`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/structured.py#L36) class in [`libs/core/langchain_core/tools/structured.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/structured.py) offers a robust solution. It operates on structured inputs defined by a Pydantic [`BaseModel`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/pyproject.toml#L84) via [`args_schema`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L439) and also supports synchronous and asynchronous execution with integrated [`run_manager`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L71) (for callbacks) and [`RunnableConfig`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/config.py#L49) handling. The [`from_function`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/simple.py#L162) class method simplifies instantiation by inferring the tool's name, description, and [`args_schema`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L439) from a provided function.

For retrieval-augmented generation (RAG) applications, the [`create_retriever_tool`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/retriever.py#L67) factory function in [`libs/core/langchain_core/tools/retriever.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/retriever.py) encapsulates a [`BaseRetriever`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/retrievers.py#L52) to create a [`Tool`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/simple.py#L30) for document lookup. This tool queries the retriever, formats the retrieved [`Document`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/base.py#L283) objects using a [`BasePromptTemplate`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/prompts/base.py#L44), and returns the formatted content, supporting both synchronous and asynchronous operations.

Additionally, the utilities in [`libs/core/langchain_core/tools/render.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/render.py) provide functions like [`render_text_description`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/render.py#L13) and [`render_text_description_and_args`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/render.py#L41) to transform [`BaseTool`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/tools/base.py#L390) objects into human-readable text descriptions, which can be useful for displaying tool information. The overall design emphasizes Pydantic for schema validation, [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) for seamless integration into expression language chains, and a robust callback system for observability. More information on the [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) protocol and LCEL can be found in [The Runnable Protocol and LCEL](https://codewiki.google/github.com/langchain-ai/langchain#core-langchain-abstractions-and-utilities-the-runnable-protocol-and-lcel), and the callback system is detailed in [Callback System](https://codewiki.google/github.com/langchain-ai/langchain#core-langchain-abstractions-and-utilities-callback-system).

### Data Handling and Indexing for RAG

link

zoom\_in

LangChain provides core abstractions for managing data within retrieval-augmented generation (RAG) pipelines and vector stores. This includes mechanisms for handling raw data, representing processed documents, transforming and compressing document content, and a robust system for indexing these documents efficiently.

The foundation for data handling lies in classes such as [`Blob`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/base.py#L57) and [`Document`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/base.py#L283). A [`Blob`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/base.py#L57) is designed to represent raw data, either held in memory or referenced by a file path, enabling document loaders to separate the concerns of data acquisition from parsing. This allows for flexible handling of various data sources and types. The [`Document`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/base.py#L283) class, on the other hand, represents a piece of processed text content with associated metadata, specifically tailored for retrieval workflows like RAG and vector stores. Both [`Blob`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/base.py#L57) and [`Document`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/base.py#L283) inherit from [`BaseMedia`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/base.py#L33), providing common fields for unique identification and metadata. These core data structures are defined in [`libs/core/langchain_core/documents/base.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/base.py).

Beyond basic data representation, LangChain offers abstract interfaces for modifying document content. The [`BaseDocumentCompressor`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/compressor.py#L19) (defined in [`libs/core/langchain_core/documents/compressor.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/compressor.py)) provides an interface for refining a list of [`Document`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/base.py#L283) objects after initial retrieval, allowing for operations like re-ranking or filtering based on a query. Similarly, the [`BaseDocumentTransformer`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/transformers.py#L16) (defined in [`libs/core/langchain_core/documents/transformers.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/transformers.py)) offers a general mechanism for applying arbitrary transformations to sequences of [`Document`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/base.py#L283) objects. Both support synchronous and asynchronous operations, with asynchronous methods often executing their synchronous counterparts in a separate thread to maintain non-blocking behavior. These abstract classes are dynamically imported through [`libs/core/langchain_core/documents/__init__.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/__init__.py).

For loading documents, the framework provides the [`BaseLoader`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/document_loaders/base.py#L26) and [`BaseBlobParser`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/document_loaders/base.py#L116) abstract interfaces (defined in [`libs/core/langchain_core/document_loaders/base.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/document_loaders/base.py)). A robust indexing mechanism is provided for managing documents within vector stores or document indices, primarily located in [`libs/core/langchain_core/indexing`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/indexing). This system addresses critical challenges such as de-duplication, efficient updates, and cleanup of outdated content. The core of this mechanism involves hashing documents to generate unique IDs, preventing redundant re-indexing of unchanged content, and tracking document states. The [`RecordManager`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/indexing/base.py#L22) (defined in [`libs/core/langchain_core/indexing/base.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/indexing/base.py)), along with its [`InMemoryRecordManager`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/indexing/base.py#L240) implementation, plays a central role by keeping a record of all indexed documents, including their hashes and last update times. This allows the system to intelligently determine which documents need to be added, updated, skipped, or deleted.

The indexing process supports various cleanup strategies (e.g., [`incremental`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/indexing/api.py#L285), [`full`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/README.md?plain=1#L60), [`scoped_full`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/indexing/api.py#L285)) to manage the lifecycle of documents in the target store. The main indexing logic is orchestrated by the [`index`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/indexing/api.py#L279) and [`aindex`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/indexing/api.py#L617) functions (found in [`libs/core/langchain_core/indexing/api.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/indexing/api.py)), which provide synchronous and asynchronous APIs, respectively. These functions handle batch processing, de-duplication within batches, and coordination with the [`RecordManager`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/indexing/base.py#L22) and the target [`VectorStore`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/vectorstores/base.py#L43) or [`DocumentIndex`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/indexing/base.py#L497). The [`DocumentIndex`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/indexing/base.py#L497) abstract base class further defines a generic interface for storing, fetching, and searching documents by ID, making it compatible with various underlying indexing systems. The entire indexing subsystem benefits from lazy loading, with components exposed via [`libs/core/langchain_core/indexing/__init__.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/indexing/__init__.py).

### Serialization and Deserialization

link

zoom\_in

LangChain provides mechanisms for converting Python objects to and from JSON, enabling persistence, transfer, and reconstruction of complex application components. This system addresses concerns such as secret management, dynamic class loading, and maintaining compatibility across different versions of the framework.

The core of this system is the [`Serializable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/serializable.py#L88) abstract base class, defined in [`libs/core/langchain_core/load/serializable.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/serializable.py). Objects that inherit from [`Serializable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/serializable.py#L88) can define how they are represented in a JSON-compatible format. This process is opt-in, requiring classes to explicitly mark themselves as serializable. During serialization, sensitive constructor arguments can be designated as secrets, which are replaced by placeholders to prevent their exposure.

Serialization functions, such as [`dumps`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/dump.py#L40) (to JSON string) and [`dumpd`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/dump.py#L71) (to dictionary representation), are available in [`libs/core/langchain_core/load/dump.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/dump.py). These functions handle [`Serializable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/serializable.py#L88) objects by invoking their defined serialization methods and include specific logic for certain nested Pydantic models. For objects that cannot be fully serialized, a [`SerializedNotImplemented`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/serializable.py#L49) representation is used to prevent errors and indicate the limitation.

Deserialization is handled by functions like [`loads`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/load.py#L185) (from JSON string) and [`load`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/load.py#L228) (from parsed Python objects) in [`libs/core/langchain_core/load/load.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/load.py). These functions employ a [`Reviver`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/load.py#L48) class which acts as an [`object_hook`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/load.py#L217) during JSON parsing. The [`Reviver`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/load.py#L48) reconstructs Python objects by dynamically importing classes based on their unique identifiers (namespace and class name) and instantiating them with their stored constructor arguments.

Security is maintained through namespace validation. The [`Reviver`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/load.py#L48) uses a whitelist of allowed Python module namespaces, defined in [`valid_namespaces`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/load.py#L54), to prevent the loading of arbitrary code. This ensures that only trusted LangChain components can be reconstructed.

Version compatibility is addressed through a system of serialization mappings, primarily located in [`libs/core/langchain_core/load/mapping.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/mapping.py). These mappings translate historical [`lc_namespace`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/mapping.py#L3) paths, used in serialized data, to their current module locations in the codebase. This allows applications to load objects that might have been saved using older or different internal module structures, facilitating backward compatibility as LangChain evolves. Additionally, explicit mappings are provided for older [`lc_namespace`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/mapping.py#L3) paths and those intended for cross-language compatibility.

The entire serialization and deserialization utility is exposed through the [`libs/core/langchain_core/load/__init__.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/load/__init__.py) file, which uses dynamic imports to efficiently load components only when they are accessed.

### API Management and Warnings

link

zoom\_in

LangChain utilizes an internal set of utilities to manage the evolution of its API, handling the lifecycle of features from their introduction as beta components to their eventual deprecation. This system is designed to provide clear communication to developers about the stability and longevity of various API elements while optimizing application performance.

Central to this system is a lazy loading mechanism, primarily implemented within [`libs/core/langchain_core/_api/__init__.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/_api/__init__.py), which defers the import of modules until their contents are explicitly requested. This approach helps to improve startup performance by avoiding the eager loading of all API helper submodules.

New or experimental features are introduced using the [`beta`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/_api/beta_decorator.py#L33) decorator, defined in [`libs/core/langchain_core/_api/beta_decorator.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/_api/beta_decorator.py). When an object marked with this decorator is accessed or instantiated by external code, a [`LangChainBetaWarning`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/_api/beta_decorator.py#L23) is issued. This warning informs developers that the API is subject to change and should be used with caution. The system ensures that these warnings are emitted only once per object and can be temporarily suppressed via a context manager. To prevent internal LangChain development from being inundated with warnings, these beta warnings are suppressed if the caller is determined to be internal to the LangChain codebase, a check performed by the [`is_caller_internal`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/_api/internal.py#L4) function from [`libs/core/langchain_core/_api/internal.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/_api/internal.py).

Similarly, the system manages deprecated features through the [`deprecated`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/_api/deprecation.py#L69) decorator and related utilities in [`libs/core/langchain_core/_api/deprecation.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/_api/deprecation.py). This decorator marks functions, classes, or properties as deprecated, issuing a [`LangChainDeprecationWarning`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/_api/deprecation.py#L31) or [`LangChainPendingDeprecationWarning`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/_api/deprecation.py#L35) upon their use. Deprecation messages are customizable, often suggesting alternative APIs and providing removal timelines. This mechanism also includes support for handling renamed parameters, automatically remapping old parameter names to new ones while issuing warnings. As with beta warnings, deprecation warnings are suppressed for internal calls to maintain a clear development environment.

Path-related utilities in [`libs/core/langchain_core/_api/path.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/_api/path.py) support these API management functions by providing methods to convert file paths into relative paths and Python import strings, which can be useful in dynamic loading scenarios.

## LangChain v1 Framework for LLM Applications

link

zoom\_in

The [`langchain_v1`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/README.md?plain=1#L11) framework provides a structured approach to developing applications powered by Large Language Models (LLMs). It encompasses core components for orchestrating AI agents, handling various LLM interactions, and integrating with external services. The framework prioritizes modularity, allowing developers to construct complex workflows from reusable building blocks.

Key aspects of the [`langchain_v1`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/README.md?plain=1#L11) framework include:

- **Agent Orchestration**: The framework facilitates the creation of AI agents capable of interacting with tools and managing their state through [`StateGraph`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain_v1/langchain/agents/factory.py#L21) workflows. This is achieved via a factory function that compiles models, tools, and system prompts into executable agents. A modular middleware system allows for injecting custom logic at various stages of an agent's operation, enabling features such as context management, sandboxed execution, PII handling, model fallback, and human-in-the-loop interventions. For further details on agent architecture and middleware, refer to [Agent Orchestration and Middleware System](https://codewiki.google/github.com/langchain-ai/langchain#langchain-v1-framework-for-llm-applications-agent-orchestration-and-middleware-system).
- **Chat Models**: A unified interface for chat models simplifies integration with diverse LLM providers. A factory function enables flexible and configurable instantiation of chat models, managing dependencies and supporting declarative methods like [`bind_tools`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain_v1/langchain/chat_models/base.py#L914) and [`with_structured_output`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/xai/langchain_xai/chat_models.py#L587) through queued operations. See [Chat Model Initialization and Configuration](https://codewiki.google/github.com/langchain-ai/langchain#langchain-v1-framework-for-llm-applications-chat-model-initialization-and-configuration) for more information.
- **Embedding Models**: The framework offers a standardized way to access and manage embedding models. A utility function dynamically instantiates embedding models from various providers, performing dependency checks to ensure seamless integration. For an in-depth understanding, refer to [Embedding Model Integration](https://codewiki.google/github.com/langchain-ai/langchain#langchain-v1-framework-for-llm-applications-embedding-model-integration).
- **Message Handling**: Standardized message types and content blocks ( [`AIMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/ai.py#L153), [`HumanMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/human.py#L9), [`SystemMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/system.py#L9), etc.) are central to AI interactions, ensuring consistency across different models and applications. The framework also provides utilities for managing message history, such as [`trim_messages`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/utils.py#L692). This mechanism promotes flexible and configurable model instantiation.

For scenarios requiring dynamic parameter adjustment, [`init_chat_model`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain_v1/langchain/chat_models/base.py#L24) can return a [`_ConfigurableModel`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain_v1/langchain/chat_models/base.py#L533) instance when [`configurable_fields`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L2592) are provided. LangChain v1 provides a streamlined approach to managing and integrating various embedding models within applications. This is achieved primarily through the [`Embeddings`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/embeddings/embeddings.py#L8) abstract base class, which establishes a consistent interface for all embedding implementations, and the [`init_embeddings`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain_v1/langchain/embeddings/base.py#L123) utility function located in [`libs/langchain_v1/langchain/embeddings/base.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain_v1/langchain/embeddings/base.py).

Users can specify a model either by its name, potentially prefixed with a provider identifier (e.g., [`'openai:text-embedding-3-small'`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain_v1/langchain/embeddings/base.py#L99)), or by separate [`model`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/prompty/langchain_prompty/core.py#L68) and [`provider`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/huggingface/langchain_huggingface/llms/huggingface_endpoint.py#L88) arguments. The utility dynamically infers the intended provider and model, ensuring flexibility in configuration.

A key aspect of this integration is its robust dependency management. Before loading a specific embedding model, [`init_embeddings`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain_v1/langchain/embeddings/base.py#L123) checks for the necessary Python package associated with that provider. If a dependency is missing, it raises an [`ImportError`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/dev_scripts.py#L28) with clear instructions, preventing runtime issues and ensuring a smooth developer experience. This dynamic import mechanism means that only the required embedding classes are loaded, optimizing resource usage.

Once the provider and model are determined, the function dynamically imports the corresponding embedding class (e.g., [`OpenAIEmbeddings`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/openai/langchain_openai/embeddings/base.py#L86) or [`BedrockEmbeddings`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain_v1/langchain/embeddings/base.py#L215)) from its respective LangChain integration package. It then instantiates and returns an [`Embeddings`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/embeddings/embeddings.py#L8) object, ready for use in LangChain applications. This approach allows developers to leverage a wide range of embedding services through a unified API, abstracting away provider-specific complexities.

At its core, the [`langchain-classic`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/README.md?plain=1#L10) package employs a dynamic import mechanism, primarily utilizing Python's [`__getattr__`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/utils/image.py#L6) and [`warnings.warn`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/utils/utils.py#L240) within its main [`__init__.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/_import_utils.py#L11) file (located at [`libs/langchain/langchain_classic/__init__.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/__init__.py)). This allows it to intercept imports of legacy components and redirect them to their new locations, such as [`langchain_community.llms`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/__init__.py#L134) or [`langchain_core.prompts`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/hub.py#L11), while simultaneously issuing deprecation warnings. For critical relocations, it might raise an [`ImportError`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/dev_scripts.py#L28) to clearly direct users to the correct package, for instance, [`langchain-experimental`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/SECURITY.md?plain=1#L55) for certain functionalities like [`LLMBashChain`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/__init__.py#L72). This approach maintains backward compatibility for older codebases while actively steering users towards the evolving structure of the LangChain library.

The internal API helpers, located within [`libs/langchain/langchain_classic/_api`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/_api), centralize mechanisms for managing these deprecations and dynamic imports. This includes defining custom warning classes like [`LangChainDeprecationWarning`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/_api/deprecation.py#L31) and providing utilities to suppress or surface these warnings, ensuring a controlled transition process.

Agent orchestration within [`langchain-classic`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/README.md?plain=1#L10) is managed through the [`libs/langchain/langchain_classic/agents`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents) directory. This area defines abstract interfaces for various agent types and features [`AgentExecutor`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/agent.py#L1012) for managing their operational loops. It facilitates the integration of tools and offers numerous agent creation functions. Many of these functionalities, particularly specific agent implementations and toolkits, are gradually being migrated to [`langchain_community`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/SECURITY.md?plain=1#L61) and [`langchain_experimental`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/scripts/lint_imports.sh#L8), with [`langchain-classic`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/README.md?plain=1#L10) acting as a bridge by dynamically redirecting these imports. See [Agent Orchestration and Deprecation Management](https://codewiki.google/github.com/langchain-ai/langchain#langchain-compatibility-layer-classic-agent-orchestration-and-deprecation-management) for more details.

The framework also includes components for chain management, where the [`Chain`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/chains/base.py#L52) abstraction defines structured sequences of LLM calls. While [`langchain-classic`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/README.md?plain=1#L10) provides various specialized chain implementations, many are marked for deprecation, with developers encouraged to adopt [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124)-based components in [`langchain_core`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L274). Similarly, LLM and chat model integrations, along with embedding management, are handled as compatibility layers, proxying calls to their new homes in [`langchain_community`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/SECURITY.md?plain=1#L61) while alerting users to these changes.

A robust testing and development environment is integral to [`langchain-classic`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/README.md?plain=1#L10). The [`Makefile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/.editorconfig#L43) at [`libs/langchain/Makefile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/Makefile) orchestrates tasks such as testing, code coverage, linting, and formatting. The [`dev.Dockerfile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/.devcontainer/docker-compose.yaml#L5) at [`libs/langchain/dev.Dockerfile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/dev.Dockerfile) sets up a consistent Dockerized development environment, including necessary system dependencies and the [`uv`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L232) package manager. Furthermore, the [`scripts`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/.editorconfig#L38) directory (found at [`libs/langchain/scripts`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/scripts)) contains utilities for architectural enforcement, including checking Python module loadability and enforcing strict import rules to prevent unauthorized dependencies between the different LangChain packages. These measures ensure the stability and architectural integrity of the [`langchain-classic`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/README.md?plain=1#L10) layer as the ecosystem evolves. See [Development, Testing, and Architectural Enforcement](https://codewiki.google/github.com/langchain-ai/langchain#langchain-compatibility-layer-classic-development-testing-and-architectural-enforcement) for more details.

### Agent Orchestration and Deprecation Management

link

zoom\_in

The [`langchain_classic`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/Makefile#L39) agent framework facilitates the creation and execution of AI agents capable of dynamic interaction with tools and external resources. This framework is characterized by its abstract interfaces, a central executor for orchestrating agent loops, and a robust mechanism for managing deprecation as components migrate to newer LangChain packages.

At its core, the framework defines abstract interfaces for agents, such as [`BaseSingleActionAgent`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/agent.py#L55) and [`BaseMultiActionAgent`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/agent.py#L221) in [`libs/langchain/langchain_classic/agents/agent.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/agent.py). These define how an agent plans its next actions or determines when to conclude its task. Concrete implementations, like [`RunnableAgent`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/agent.py#L389), integrate with LangChain's [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) interface, allowing agents to be composable within larger LangChain Expression Language (LCEL) chains. See [The Runnable Protocol and LCEL](https://codewiki.google/github.com/langchain-ai/langchain#core-langchain-abstractions-and-utilities-the-runnable-protocol-and-lcel) for more details.

The [`AgentExecutor`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/agent.py#L1012) in [`libs/langchain/langchain_classic/agents/agent.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/agent.py) serves as the primary orchestrator for agent execution. It manages the iterative process of an agent planning, executing tools, processing observations, and deciding on subsequent steps until a final answer is reached or a predefined stopping condition is met. This executor supports configurable limits on iterations and execution time, and provides flexible error handling for situations like output parsing failures. For an in-depth understanding of how an agent’s intermediate steps are transformed into LLM-readable formats, refer to [Agent Scratchpad Formatting](https://codewiki.google/github.com/langchain-ai/langchain#langchain-compatibility-layer-classic-agent-orchestration-and-deprecation-management-agent-scratchpad-formatting).

The [`langchain_classic`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/Makefile#L39) agent framework extensively uses dynamic imports and deprecation warnings to manage the migration of numerous agent types and toolkits. The [`__init__.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/_import_utils.py#L11) file in [`libs/langchain/langchain_classic/agents/__init__.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/__init__.py) and the [`agent_toolkits`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/chains/api/base.py#L107) directory leverage mechanisms like [`__getattr__`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/utils/image.py#L6) to intercept attribute access. This allows for components that have been moved to [`langchain_community`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/SECURITY.md?plain=1#L61) or [`langchain_experimental`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/scripts/lint_imports.sh#L8) to be dynamically loaded, while simultaneously providing clear [`ImportError`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/dev_scripts.py#L28) messages or warnings that guide users toward the new module locations. This strategy ensures backward compatibility for existing codebases while actively encouraging migration to the modularized LangChain ecosystem.

Agent creation functions like [`initialize_agent`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/initialize.py#L24) in [`libs/langchain/langchain_classic/agents/initialize.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/initialize.py) and various [`load_agent`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/loading.py#L102) functions in [`libs/langchain/langchain_classic/agents/loading.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/loading.py) facilitate the setup and configuration of agents from diverse sources, including predefined agent types or serialized configurations. These functions are progressively being marked as deprecated, signaling a shift towards newer, often [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124)-based, approaches for agent construction and loading.

Within the [`langchain_classic`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/Makefile#L39) framework, various agent patterns were supported. For instance, specific implementations catered to conversational AI workflows, such as [`ChatAgent`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/chat/base.py#L36), [`ConversationalAgent`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/conversational/base.py#L34), and [`ConversationalChatAgent`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/conversational_chat/base.py#L37). These agents handled tool integration, maintained chat history, and managed prompt construction for diverse interactions. However, these patterns are now deprecated in favor of more modern, [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124)-based paradigms. Similarly, the [`json_chat`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/__init__.py#L35) agent provided a structure for agents that strictly enforced JSON-formatted output for actions and final answers, leveraging specific prompt templates and output parsers to ensure machine-readable and consistent interaction. See [JSON Chat Agent Structure](https://codewiki.google/github.com/langchain-ai/langchain#langchain-compatibility-layer-classic-agent-orchestration-and-deprecation-management-json-chat-agent-structure) for additional context.

#### Conversational Agent Patterns

link

zoom\_in

The [`langchain_classic`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/Makefile#L39) library includes several deprecated agent implementations designed for conversational AI workflows, specifically [`ChatAgent`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/chat/base.py#L36), [`ConversationalAgent`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/conversational/base.py#L34), and [`ConversationalChatAgent`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/conversational_chat/base.py#L37). These agents demonstrate earlier approaches to integrating tools, managing chat history, and handling prompt construction and output parsing for language models. Their functionality has largely been superseded by newer, Runnable-based paradigms, with a focus on structured output and composability.

The [`ChatAgent`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/chat/base.py#L36), primarily defined in [`libs/langchain/langchain_classic/agents/chat/base.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/chat/base.py), is built around a [`ChatPromptTemplate`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/prompts/chat.py#L774) to construct prompts for conversational models. It leverages predefined string templates (found in [`libs/langchain/langchain_classic/agents/chat/prompt.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/chat/prompt.py)) to guide the LLM's behavior, including system messages, tool descriptions, and instructions for JSON-formatted output. The [`ChatOutputParser`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/chat/output_parser.py#L14) in [`libs/langchain/langchain_classic/agents/chat/output_parser.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/chat/output_parser.py) is responsible for interpreting the LLM's raw text output, distinguishing between structured [`AgentAction`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/agents.py#L42) objects (for tool use) and [`AgentFinish`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/agents.py#L140) objects (for final answers) based on patterns and explicit markers.

Similarly, the [`ConversationalAgent`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/conversational/base.py#L34), implemented in [`libs/langchain/langchain_classic/agents/conversational/base.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/conversational/base.py), provides a framework for agents that maintain a dialogue while also being able to invoke tools. It constructs prompts by combining a [`PREFIX`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/mrkl/prompt.py#L1), tool descriptions, and [`FORMAT_INSTRUCTIONS`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/chat/prompt.py#L2) (from [`libs/langchain/langchain_classic/agents/conversational/prompt.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/conversational/prompt.py)) to guide the LLM. Its [`ConvoOutputParser`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/conversational/output_parser.py#L10) (in [`libs/langchain/langchain_classic/agents/conversational/output_parser.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/conversational/output_parser.py)) processes LLM responses to identify either final answers (indicated by an [`ai_prefix`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/memory/entity.py#L475)) or tool actions through regular expression matching.

The [`ConversationalChatAgent`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/conversational_chat/base.py#L37), detailed in [`libs/langchain/langchain_classic/agents/conversational_chat/base.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/conversational_chat/base.py), represents another iteration of conversational agents. This agent specifically constructs [`ChatPromptTemplate`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/prompts/chat.py#L774) s that integrate chat history, tool descriptions, and a "scratchpad" for intermediate thoughts and observations, converting them into a sequence of [`BaseMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/base.py#L93) objects for the LLM. The [`ConvoOutputParser`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/conversational/output_parser.py#L10) for this agent (in [`libs/langchain/langchain_classic/agents/conversational_chat/output_parser.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/conversational_chat/output_parser.py)) is designed to extract JSON-formatted responses, potentially embedded within Markdown, to determine whether the LLM is making a tool call or providing a final answer. The prompt templates for this agent, located in [`libs/langchain/langchain_classic/agents/conversational_chat/prompt.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/conversational_chat/prompt.py), explicitly instruct the LLM to output structured JSON for either tool invocation or final answers, aiming for machine-readable and consistent interaction.

These agents collectively showcase the evolution of conversational AI patterns within LangChain, moving from more ad-hoc parsing and string templating towards increasingly structured and robust methods for LLM interaction and tool orchestration. The explicit deprecation of these components signals a shift towards newer, more flexible, and composable architectures that are better aligned with the LangChain Expression Language (LCEL) and the [`Runnable`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/runnables/base.py#L124) protocol, as discussed in [The Runnable Protocol and LCEL](https://codewiki.google/github.com/langchain-ai/langchain#core-langchain-abstractions-and-utilities-the-runnable-protocol-and-lcel).

#### Agent Scratchpad Formatting

link

zoom\_in

The agent scratchpad formatting utilities within [`langchain_classic`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/Makefile#L39) are designed to convert an agent's intermediate steps (pairs of actions and observations) into various formats suitable for consumption by Large Language Models (LLMs). This adaptation is crucial for maintaining the agent's contextual awareness and enabling diverse prompting strategies across different LLM architectures.

One common approach is to format these steps into a single string log. The [`format_log_to_str`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/format_scratchpad/log.py#L4) function in [`libs/langchain/langchain_classic/agents/format_scratchpad/log.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/format_scratchpad/log.py) takes [`AgentAction`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/agents.py#L42) objects and their observations and reconstructs a cohesive string representing the agent's thought process, concatenating action logs, observations, and prefixes for the next thought. This is useful for LLMs that process sequential text inputs.

For chat-based LLMs, where interactions are typically message-oriented, the [`format_log_to_messages`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/format_scratchpad/log_to_messages.py#L5) function in [`libs/langchain/langchain_classic/agents/format_scratchpad/log_to_messages.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/format_scratchpad/log_to_messages.py) transforms intermediate steps into a list of [`BaseMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/base.py#L93) objects, specifically [`AIMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/ai.py#L153) for agent actions and [`HumanMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/human.py#L9) for observations. This allows the agent's history to be presented as a conversational flow.

Specialized formats are also provided for LLMs with advanced capabilities, such as OpenAI's function-calling models. The [`format_to_openai_function_messages`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/format_scratchpad/openai_functions.py#L68) function, defined in [`libs/langchain/langchain_classic/agents/format_scratchpad/openai_functions.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/format_scratchpad/openai_functions.py), converts [`AgentAction`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/agents.py#L42) and observations into [`FunctionMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/function.py#L15) and [`AIMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/ai.py#L153) objects. This allows the agent to communicate tool invocation requests and their results in a structured manner that OpenAI models can interpret. Similarly, for generic tool interactions, the [`format_to_tool_messages`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/format_scratchpad/tools.py#L51) function in [`libs/langchain/langchain_classic/agents/format_scratchpad/tools.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/format_scratchpad/tools.py) creates [`ToolMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/tool.py#L26) objects for tool-specific actions and [`AIMessage`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/messages/ai.py#L153) for other action types, ensuring that tool calls and their outcomes are clearly delineated. A re-export for OpenAI-specific tool messages is available as [`format_to_openai_tool_messages`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/format_scratchpad/openai_tools.py#L2) in [`libs/langchain/langchain_classic/agents/format_scratchpad/openai_tools.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/format_scratchpad/openai_tools.py).

Additionally, agents requiring XML-formatted inputs or outputs can utilize the [`format_xml`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/format_scratchpad/xml.py#L21) function in [`libs/langchain/langchain_classic/agents/format_scratchpad/xml.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/langchain_classic/agents/format_scratchpad/xml.py). This utility converts intermediate steps into an XML string, with built-in mechanisms to escape potential XML tags within tool inputs or observations, thereby preventing structural conflicts and ensuring well-formed XML output. These diverse formatting options collectively enable [`langchain_classic`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/langchain/Makefile#L39) agents to integrate seamlessly with various LLM types and their distinct input requirements.

## LLM Model Profiles

zoom\_in

This section describes the centralized system for accessing and managing LLM capabilities, features, and constraints through structured model profiles. It explains how these profiles are used to define and retrieve information about various language models, ensuring consistent interaction and integration within the LangChain framework.

The [`langchain-model-profiles`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/README.md?plain=1#L1) package provides programmatic access to model capabilities via a [`.profile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/README.md?plain=1#L21) property on LangChain chat models. This allows developers to query model-specific features such as context window sizes, supported modalities for input and output, structured output support, and tool calling capabilities. The core schema for these profiles is defined by the [`ModelProfile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/model_profile.py#L10) [`TypedDict`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/utils/git.py#L10) in \[/langchain-ai/langchain/libs/model-profiles/langchain\_model\_profiles/model\_profile.py\]. An API function, [`get_model_profile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/model_profile.py#L129), facilitates the retrieval of these profiles, handling normalization of provider and model IDs for consistent access.

The system relies on a hierarchical approach to data management. Base model data is sourced from [`models.json`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/scripts/refresh_data.py#L46) (originating from the [`models.dev`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/Makefile#L70) project), as documented in \[/langchain-ai/langchain/libs/model-profiles/langchain\_model\_profiles/data/ATTRIBUTION.txt\]. This base data is then augmented with LangChain-specific information through TOML files organized within the \[/langchain-ai/langchain/libs/model-profiles/langchain\_model\_profiles/data/augmentations\] directory. These augmentations can be applied at both the provider level (e.g., for all models from a specific provider) and the individual model level, allowing for granular overrides and customization of capabilities. A [`_DataLoader`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/_data_loader.py#L15) class, defined in \[/langchain-ai/langchain/libs/model-profiles/langchain\_model\_profiles/\_data\_loader.py\], manages the loading and merging of this data, ensuring that model-level augmentations take precedence over provider-level ones, which in turn override the base data.

To maintain up-to-date model information, a [`refresh_data`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/Makefile#L1) script, located in \[/langchain-ai/langchain/libs/model-profiles/scripts/refresh\_data.py\], automates the process of downloading, filtering, and persisting model data from the [`models.dev`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/Makefile#L70) API into the local [`models.json`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/scripts/refresh_data.py#L46) file. This ensures that the model profiles used within LangChain accurately reflect the latest capabilities and constraints of the integrated LLMs.

### Model Profile Structure and Retrieval

link

zoom\_in

The model profile system provides a standardized way to access and manage the capabilities and constraints of various large language models (LLMs) within the LangChain framework. This system centers on the [`ModelProfile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/model_profile.py#L10) TypedDict and the [`get_model_profile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/model_profile.py#L129) public API function, which together enable consistent retrieval of model-specific information.

The [`ModelProfile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/model_profile.py#L10) is a schema that defines the characteristics of an LLM, including attributes such as [`max_input_tokens`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/README.md?plain=1#L53), [`image_inputs`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/model_profile.py#L18), [`tool_calling`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/language_models/chat_models.py#L301), and [`structured_output`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/README.md?plain=1#L50). All fields within this schema are optional, allowing for flexible and partial definitions depending on the information available for a given model. This design ensures type safety and a clear contract for how model capabilities are represented.

The primary entry point for retrieving model information is the [`get_model_profile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/model_profile.py#L129) function, which accepts a [`provider`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/huggingface/langchain_huggingface/llms/huggingface_endpoint.py#L88) and [`model`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/prompty/langchain_prompty/core.py#L68) identifier. This function includes internal logic to normalize these identifiers, translating LangChain-specific naming conventions (e.g., for Google or Amazon Bedrock models) into a standardized format. This normalization is crucial for querying the underlying data source consistently, regardless of how a particular model or provider is referenced externally. Once the identifiers are standardized, the function fetches the relevant profile data and maps it to the [`ModelProfile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/model_profile.py#L10) schema, providing a structured representation of the model's features and limitations.

The actual loading and merging of model profile data are handled by an internal [`_DataLoader`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/_data_loader.py#L15) component, which combines base data from a [`models.json`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/scripts/refresh_data.py#L46) file with hierarchical augmentations defined in TOML files. This allows for granular customization of model profiles at both the provider and individual model levels, ensuring that LangChain can adapt to evolving model landscapes and specific application requirements. For more details on how this data is managed and augmented, refer to [Hierarchical Data Loading and Augmentation](https://codewiki.google/github.com/langchain-ai/langchain#llm-model-profiles-hierarchical-data-loading-and-augmentation).

### Hierarchical Data Loading and Augmentation

link

zoom\_in

The [`_DataLoader`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/_data_loader.py#L15) class orchestrates the loading and merging of model profile data, providing a unified source of information about various language models within LangChain. This process begins with a base [`models.json`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/scripts/refresh_data.py#L46) file, which is then progressively augmented with LangChain-specific configurations through TOML files.

The initial dataset, [`models.json`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/scripts/refresh_data.py#L46), is sourced from the [`models.dev`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/Makefile#L70) project. Attribution for this base data is documented in [`libs/model-profiles/langchain_model_profiles/data/ATTRIBUTION.txt`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/data/ATTRIBUTION.txt), which also notes that the original data has been extended for LangChain's requirements.

Augmentations are applied hierarchically to customize model capabilities. These customizations are defined in TOML files located within the [`libs/model-profiles/langchain_model_profiles/data/augmentations`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/data/augmentations) directory. The system supports two levels of augmentation:

1. **Provider-level augmentations**: These are specified in [`augmentations/providers/{provider}.toml`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/_data_loader.py#L46) files. They override base data for all models associated with a particular provider, allowing for consistent configuration across a provider's offerings.
2. **Model-level augmentations**: These are found in [`augmentations/models/{provider}/{model}.toml`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/_data_loader.py#L47) files. These augmentations take precedence over both base data and provider-level configurations, enabling fine-grained control over individual model profiles.

This layered approach ensures that LangChain can manage a flexible and adaptable set of model capabilities, allowing for both broad provider-wide settings and specific adjustments for individual models. The [`_DataLoader`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/langchain_model_profiles/_data_loader.py#L15) ensures that this merging process happens efficiently, caching the result after the initial load. The structure and retrieval of these profiles are managed by [Model Profile Structure and Retrieval](https://codewiki.google/github.com/langchain-ai/langchain#llm-model-profiles-model-profile-structure-and-retrieval).

### Model Profile Data Management

Model profile data management is primarily handled by the automated [`refresh_data`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/Makefile#L1) script located at \[ [`libs/model-profiles/scripts/refresh_data.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/scripts/refresh_data.py)\](/langchain-ai/langchain/libs/model-profiles/scripts/refresh\_data.py). This script is designed to ensure that the local [`models.json`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/scripts/refresh_data.py#L46) file, which contains critical information about various language models, remains up-to-date. The process involves downloading the latest model data from [`models.dev`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/Makefile#L70), applying a filtering mechanism to retain only relevant providers, and then persisting this filtered data locally. This approach ensures that the LangChain framework consistently has access to current and relevant model capabilities and constraints.

The script's functionality encompasses several key steps: it initiates an HTTP GET request to [`https://models.dev/api.json`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/scripts/refresh_data.py#L44) to fetch the comprehensive model catalog. Upon successful download, the script filters this data to include only models from a predefined subset of providers. This filtering step optimizes the local data store by removing unneeded information. Finally, the processed and filtered model data is written to the local [`models.json`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/model-profiles/scripts/refresh_data.py#L46) file, ensuring it is consistently formatted for readability and maintainability. This automated data management pipeline supports the reliable operation of the LLM Model Profiles system, as discussed in [LLM Model Profiles](https://codewiki.google/github.com/langchain-ai/langchain#llm-model-profiles).

Compatibility functions ensure smooth conversion between LangChain's internal content blocks and annotations and Anthropic's native API formats, bridging structural differences in how content and citations are represented.

For advanced use cases, the integration includes experimental middleware components that can extend agent capabilities. These include features like prompt caching, integration of Anthropic's native [`bash`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L230) tool, and client-side implementations of text editor, memory, and file search tools, enabling agents to interact with virtual or local file systems. For image-based queries, [`similarity_search_by_image`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/chroma/langchain_chroma/vectorstores.py#L899) and [`similarity_search_by_image_with_relevance_score`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/chroma/langchain_chroma/vectorstores.py#L940) are available, requiring an embedding function capable of processing images. To enhance the diversity of search results, the [`Chroma`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/chroma/langchain_chroma/vectorstores.py#L155) class also implements Maximal Marginal Relevance (MMR) through [`max_marginal_relevance_search`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/vectorstores/base.py#L652) and [`max_marginal_relevance_search_by_vector`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/vectorstores/base.py#L717).

Beyond data management and retrieval, the [`Chroma`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/chroma/langchain_chroma/vectorstores.py#L155) class also offers functionalities for collection administration, such as [`fork`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/chroma/langchain_chroma/vectorstores.py#L492) to create new instances with forked collections, [`delete_collection`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/chroma/langchain_chroma/vectorstores.py#L1078) to remove the current collection, and [`reset_collection`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/chroma/langchain_chroma/vectorstores.py#L1083) to clear and reinitialize it. Utility functions assist in converting raw ChromaDB results into LangChain's [`Document`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/base.py#L283) objects and dynamically selecting relevance scoring functions based on the collection's distance metric.

The [`text-splitters`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/README.md?plain=1#L14) library provides utilities for segmenting text into manageable chunks, a crucial step in preparing data for many Large Language Model (LLM) applications. This library supports diverse strategies tailored to various document types and programming languages.

At its core, the library aims to preserve context and meaning when breaking down large documents. It offers a unified framework for text segmentation and chunking, with various specialized splitters. The fundamental interface for these operations is defined by the [`TextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py#L44) abstract base class in [`libs/text-splitters/langchain_text_splitters/base.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py). This base class establishes methods for splitting text, creating and splitting documents, and managing parameters like chunk size, chunk overlap, and length functions. It also facilitates integration with document transformation pipelines.

The library includes specialized splitters:

- **Character-based Splitters** in [`libs/text-splitters/langchain_text_splitters/character.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/character.py) handle basic splitting by a character or regular expression. The [`RecursiveCharacterTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/character.py#L81) offers a more advanced approach, using a list of separators recursively to break down text while attempting to keep paragraphs and structural elements intact. This includes support for various programming languages and document formats, configuring separators to maintain structural integrity.

- **HTML Splitters** in [`libs/text-splitters/langchain_text_splitters/html.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/html.py) parse and segment HTML content. [`HTMLHeaderTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/html.py#L83) splits based on header tags, associating content with its hierarchical context. [`HTMLSectionSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/html.py#L338) uses XSLT transformations to convert certain tags into headers for structured splitting. [`HTMLSemanticPreservingSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/html.py#L519) is an experimental option designed to maintain semantic structure by handling media and links while filtering tags.

- **JSON Splitters** are addressed by [`RecursiveJsonSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/json.py#L12) in [`libs/text-splitters/langchain_text_splitters/json.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/json.py), which segments hierarchical JSON data into smaller, manageable chunks based on specified size constraints.

- **Code-Specific Splitters** such as [`PythonCodeTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/python.py#L11) in [`libs/text-splitters/langchain_text_splitters/python.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/python.py), [`JSFrameworkTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/jsx.py#L9) in [`libs/text-splitters/langchain_text_splitters/jsx.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/jsx.py) (for JSX, Vue, Svelte), and [`LatexTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/latex.py#L11) in [`libs/text-splitters/langchain_text_splitters/latex.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/latex.py) are designed to handle code and markup languages by leveraging language-specific separators to maintain code block integrity.

- **Markdown Splitters** in [`libs/text-splitters/langchain_text_splitters/markdown.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/markdown.py) provide options like [`MarkdownTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/markdown.py#L14) for basic Markdown, [`MarkdownHeaderTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/markdown.py#L23) for header-based splitting, and [`ExperimentalMarkdownSyntaxTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/markdown.py#L284) for granular control over Markdown syntax elements.

### Core Text Splitter Interface and Tokenization

link

zoom\_in

Text splitting within LangChain is centered around the [`TextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py#L44) abstract base class, defined in [`libs/text-splitters/langchain_text_splitters/base.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py). This class provides a standardized interface for breaking down large texts into smaller, manageable chunks, which is fundamental for many language model applications. It supports configurable parameters such as [`chunk_size`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/openai/langchain_openai/embeddings/base.py#L226), which specifies the maximum size of each chunk, and [`chunk_overlap`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/jsx.py#L32), which determines the degree of overlap between consecutive chunks to maintain context.

The [`TextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py#L44) integrates with the [`BaseDocumentTransformer`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/transformers.py#L16) interface, enabling it to process and transform [`Document`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/langchain_core/documents/base.py#L283) objects within a larger data pipeline. This allows for flexible workflows where text splitting can be combined with other document processing steps.

For scenarios requiring token-based splitting, the [`TokenTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py#L241) (also defined in [`libs/text-splitters/langchain_text_splitters/base.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py)) extends [`TextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py#L44) to perform segmentation based on token counts rather than character counts. It typically utilizes external tokenization libraries like [`tiktoken`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/openai/Makefile#L15) to accurately measure chunk lengths in terms of tokens. The utility function [`split_text_on_tokens`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py#L349) further supports this functionality by splitting text into token-based chunks, respecting token limits and overlap.

To facilitate integration with various tokenization models, the [`TextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py#L44) provides factory methods like [`from_huggingface_tokenizer`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py#L170) and [`from_tiktoken_encoder`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py#L191). These methods allow for the creation of [`TextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py#L44) instances pre-configured with the appropriate length functions for Hugging Face or [`tiktoken`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/openai/Makefile#L15) tokenizers. Additionally, a [`Language`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py#L303) enumeration is provided, which is used to specify language-specific configurations for specialized code splitters found in other modules, ensuring structural integrity when processing programming languages.

The [`langchain-text-splitters`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/pyproject.toml#L40) library provides specialized tools for segmenting structured document types, such as HTML, JSON, and Markdown, into smaller, manageable chunks. These splitters aim to maintain the original structure and context of the content, which is crucial for downstream processing by language models.

For HTML content, three distinct strategies are available within [`libs/text-splitters/langchain_text_splitters/html.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/html.py). The [`HTMLSectionSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/html.py#L338) uses XSLT transformations to convert specific HTML tags into headers, enabling splitting into logical sections. An experimental option, the [`HTMLSemanticPreservingSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/html.py#L519), attempts to maintain the semantic structure by handling media, links, and filtering tags, then further splitting large chunks. All HTML splitters use [`BeautifulSoup`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/html.py#L38) for parsing and [`lxml`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/pyproject.toml#L34) for XSLT transformations when applicable.

This splitter breaks down hierarchical JSON objects into chunks based on configurable [`max_chunk_size`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/json.py#L21) and [`min_chunk_size`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/json.py#L23), ensuring that the structural integrity of the JSON is preserved as much as possible across the splits.

For Markdown documents, the library offers several splitters in [`libs/text-splitters/langchain_text_splitters/markdown.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/markdown.py). The [`MarkdownTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/markdown.py#L14) extends the generic recursive character splitting by using Markdown-specific separators. The [`MarkdownHeaderTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/markdown.py#L23) parses Markdown content and splits it into chunks based on specified header levels, associating content with its parent headers to preserve logical document flow. An [`ExperimentalMarkdownSyntaxTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/markdown.py#L284) offers more granular control, preserving whitespace and treating elements like code blocks and horizontal rules as distinct entities with associated metadata.

These specialized splitters complement the core text splitter interface described in [Core Text Splitter Interface and Tokenization](https://codewiki.google/github.com/langchain-ai/langchain#text-splitting-strategies-core-text-splitter-interface-and-tokenization) by offering tailored solutions for documents where structural awareness is paramount for effective chunking.

Specialized text splitters are available for various programming languages and code formats, designed to preserve the structural integrity of code blocks and maintain contextual relevance during text segmentation. These splitters extend the functionality of the [`RecursiveCharacterTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/character.py#L81), leveraging its ability to define language-specific separators.

The [`RecursiveCharacterTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/character.py#L81) in [`libs/text-splitters/langchain_text_splitters/character.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/character.py) includes a [`from_language`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/character.py#L154) class method that configures separators based on common programming languages like Python, C, Java, JavaScript, and Rust, as well as document formats such as Markdown and LaTeX. This method utilizes [`get_separators_for_language`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/character.py#L172) to retrieve a predefined list of regex patterns tailored to split code effectively, prioritizing structural elements like function and class definitions, and control flow statements.

For Python code, [`PythonCodeTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/python.py#L11) in [`libs/text-splitters/langchain_text_splitters/python.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/python.py) specifically handles Python syntax by using a set of Python-specific separators to keep logical code blocks together. Similarly, [`LatexTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/latex.py#L11) in [`libs/text-splitters/langchain_text_splitters/latex.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/latex.py) is tailored for LaTeX documents, applying LaTeX-specific splitting points to preserve document structure.

The [`JSFrameworkTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/jsx.py#L9) in [`libs/text-splitters/langchain_text_splitters/jsx.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/jsx.py) addresses the unique challenges of JavaScript framework code, including JSX, Vue, and Svelte. This splitter dynamically identifies custom component tags within the input text and combines them with standard JavaScript syntax elements and newlines to create natural code boundaries. This dynamic generation of separators ensures adaptability to diverse codebases and custom components, resulting in semantically meaningful chunks for front-end framework code.

The overarching aim of these language-specific splitters is to enable precise text segmentation that respects the inherent structure of code and structured documents, which is crucial for tasks like code analysis, documentation generation, and language model processing. Further details on the core splitter interfaces and tokenization can be found in [Core Text Splitter Interface and Tokenization](https://codewiki.google/github.com/langchain-ai/langchain#text-splitting-strategies-core-text-splitter-interface-and-tokenization).

### NLP-Based and Sentence Transformer Splitters

link

zoom\_in

Text splitters that leverage Natural Language Processing (NLP) libraries are designed to perform robust sentence segmentation, which is often crucial for maintaining contextual integrity when chunking documents. These splitters integrate with specialized NLP tools to intelligently break down text based on linguistic structures rather than just arbitrary character counts.

The [`NLTKTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/nltk.py#L17) within the [`langchain_text_splitters`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/Makefile#L24) library uses the NLTK (Natural Language Toolkit) library for general-purpose sentence tokenization. It can split text into sentences, supporting various languages. Similarly, the [`SpacyTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/spacy.py#L24) utilizes the spaCy library, offering robust sentence segmentation with configurable pipelines, allowing for trade-offs between processing speed and linguistic accuracy. For languages with distinct linguistic characteristics, such as Korean, the [`KonlpyTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/konlpy.py#L17) specifically integrates with the [`konlpy`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/pyproject.toml#L76) package to perform sentence segmentation tailored for Korean text.

Beyond sentence-level splitting, the [`SentenceTransformersTokenTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/sentence_transformers.py#L20) addresses token-based text splitting using [`SentenceTransformer`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/sentence_transformers.py#L12) models. This splitter respects token limits and the maximum sequence length of the underlying model, making it suitable for applications where chunking by tokens (rather than characters or sentences) is necessary, especially when feeding text to transformer-based language models. All these specialized splitters inherit from the [`TextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py#L44) base class, ensuring a consistent interface for managing parameters like [`chunk_size`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/openai/langchain_openai/embeddings/base.py#L226) and [`chunk_overlap`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/jsx.py#L32). For an overview of the core text splitter interface, see [Core Text Splitter Interface and Tokenization](https://codewiki.google/github.com/langchain-ai/langchain#text-splitting-strategies-core-text-splitter-interface-and-tokenization).

### Development Workflow and Testing

link

zoom\_in

The [`text-splitters`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/README.md?plain=1#L14) library employs a robust development workflow and testing infrastructure managed primarily through a [`Makefile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/.editorconfig#L43) at \[/langchain-ai/langchain/libs/text-splitters/Makefile\]. This system orchestrates various tasks, including comprehensive testing, code quality checks, and dependency validation.

The [`Makefile`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/.editorconfig#L43) supports multiple testing modes:

- **Unit Tests**: These verify individual components using [`pytest`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/fireworks/tests/integration_tests/test_llms.py#L10) and can be run in parallel.
- **Integration Tests**: These validate interactions with external libraries and complex scenarios.
- **Extended Tests**: These are a subset of unit tests that require additional dependencies, listed in \[/langchain-ai/langchain/libs/text-splitters/extended\_testing\_deps.txt\].
- **Continuous Testing**: A watch mode automatically re-runs unit tests upon file changes.
- **Performance Profiling**: Tests can be profiled to identify performance bottlenecks.

Code quality is maintained through [`ruff`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/Makefile#L19) for linting and formatting, along with [`mypy`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L261) for static type checking. These tools ensure adherence to coding standards and type correctness across the codebase.

Furthermore, the [`text-splitters`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/README.md?plain=1#L14) library incorporates scripting utilities located in the \[/langchain-ai/langchain/libs/text-splitters/scripts\] directory to enforce architectural constraints and prevent unwanted dependencies. The [`check_imports.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/Makefile#L32) script identifies [`ImportError`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/cli/langchain_cli/dev_scripts.py#L28) exceptions by dynamically loading Python files, while [`lint_imports.sh`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/Makefile#L52) prevents direct imports from core LangChain libraries (e.g., [`langchain`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L1), [`langchain_experimental`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/core/scripts/lint_imports.sh#L8), [`langchain_community`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/SECURITY.md?plain=1#L61)), ensuring a clean and consistent dependency structure.

The testing suite, housed in the \[/langchain-ai/langchain/libs/text-splitters/tests\] directory, is divided into [`unit_tests`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L73) and [`integration_tests`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L74). The [`unit_tests`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L73) cover various splitting algorithms, document and metadata management, language-specific code splitting, and structured text processing for formats like Markdown and HTML. Of particular note is the security testing for HTML splitters, which includes checks against vulnerabilities such as XXE attacks to ensure safe processing of untrusted content. The [`integration_tests`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L74) focus on verifying external integrations, such as NLP-based splitters ( [`NLTKTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/nltk.py#L17), [`SpacyTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/spacy.py#L24)) and token-based splitters ( [`TokenTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/base.py#L241), [`SentenceTransformersTokenTextSplitter`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/text-splitters/langchain_text_splitters/sentence_transformers.py#L20)), confirming their correct operation with external tokenizers and models. The [`conftest.py`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/standard-tests/langchain_tests/unit_tests/chat_models.py#L697) file within [`unit_tests`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/AGENTS.md?plain=1#L73) plays a crucial role in configuring [`pytest`](https://github.com/langchain-ai/langchain/blob/52b1516d44897e3961781b1ed36f48eaa51b8b33/libs/partners/fireworks/tests/integration_tests/test_llms.py#L10) with custom options and markers, enabling conditional test execution based on package availability or specific test run modes.
